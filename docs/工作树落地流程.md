## 一、改动分三类，落地路径不同

| 类型 | 识别方法 | 落地方式 |
|---|---|---|
| **A. 分支工作树** | `git worktree list` 显示 `[branch]` | 主仓库 `git merge <branch>`；风险最低 |
| **B. DSH 隔离工作树** | `git worktree list` 显示 `(detached HEAD)`，路径含 `.dsh/worktrees/<hash>/` | **必须先建分支再提交**（见 §二.1），然后 merge |
| **C. 主仓库自身未提交** | 主仓库 `git status` 有 ` M` / `??` | 普通 `git add` + `git commit` |

## 二、三个坑（其中两个会真的丢东西/回退）

### 1. DSH 隔离工作树是 detached HEAD —— 直接 commit 会变游离对象

```bash
git -C <worktree> switch -c <branch>     # ① 先建分支，再提交
git -C <worktree> add -A && git -C <worktree> commit -m "..."
git merge <branch>                        # ② 回主仓库合并
# ③ 确认合并完成后再 worktree remove —— 未跟踪文件会随工作树一起删除
```

### 2. 主仓库合并后必须重灌主库（DB 隔离的反向坑）★最隐蔽

`src/data/heroes.ts` 的 `worktreeName()`（与 `scripts/db-config.mjs` 同步）按路径推导库名：

- DSH 工作树 `.dsh/worktrees/<hash>/...` → 库 `stzb战斗系统_dsh_<hash>`
- **主仓库 `Desktop/战斗系统` → 主库 `stzb战斗系统`**

后果：新武将/新挂槽的数据在 DSH 工作树里能过测试（走它自己的库），**一合回主仓库就红**——因为主库是旧的、且 MySQL 可达时**不会回退 JSON**。
本次实测：合并 `hero-mechanics-cont` 后 3 个测试失败（h811 / h794 / h615 的 `main_skill_id` 为空），而 `web/data/heroes.json` 里其实是对的。

修法（AGENTS.md 记录的数据链）：

```bash
node scripts/build_heroes_seed.mjs   # → scripts/seed_heroes.sql
node scripts/seed_db.mjs             # 只动 heroes 表：DELETE FROM heroes + INSERT
node scripts/gen_skill_data.mjs      # → web/data/skill_grades.json / skill_desc.json
node scripts/export_web_data.mjs     # → web/data/heroes.json
```

排查用（只读）：`SELECT main_skill_id FROM heroes WHERE id IN (...)`，对比 JSON 即可确认是「库旧」而不是「代码错」。

### 3. 生成物冲突不要手工解

`docs/下架武将清单.md` 由 `npx tsx scripts/gen_offline_report.mts` 生成。冲突时**取 main 侧再重跑生成器**，不要手工挑 hunk——否则会把口径改回旧版本（本次 508943b 写的是「上架 68」，而当前权威口径是 74）。

## 三、固定动作（每棵树都过一遍）

1. **算清真实入库文件数**：`git check-ignore -v <路径>` 逐条确认忽略规则命中，再 `git ls-files -o --exclude-standard <dir>` 数**实际**会入库的文件。
   案例：`android/` 目录 2860 文件 / 119 MB → 实际只有 **58 个**入库（Capacitor 的 `android/.gitignore` 已忽略 `.gradle/`、`build/`、`local.properties`、`keystore.properties`、`app/src/main/assets/public`）。
2. **验证门槛**：`npx tsc --noEmit`（exit 0）+ `npx vitest run`（全绿，含 `tests/golden.test.ts` 字节一致）。
3. **提交后查机密**：`git ls-tree -r HEAD --name-only <dir> | Select-String 'keystore|local.properties|\.gradle/|/build/|\.apk$'` → 期望零命中。
4. **推送后确认**：`git fetch --quiet; git rev-list --left-right --count origin/main...main` → `0 0`。

## 四、行尾漂移（生成器的已知噪声）

`build_heroes_seed.mjs` / `gen_skill_data.mjs` / `export_web_data.mjs` 重跑后文件可能显示 ` M`，但 **`git diff --numstat` 输出为空** = 纯 CRLF/LF 漂移，内容一致 → `git checkout -- <file>` 丢弃即可。
（`docs/下架武将清单.md` 重跑只会有「生成时间」一行变化，那是真实变更，应保留提交。）

## 八、构建/部署链（与提交解耦）

- 前端改动要 `npm run web:build`（`vite build` → `dist/`）→ 部署 `gh-pages` 分支后玩家才看得到；
- 安卓壳要 `npx cap sync android` 才会把新前端拷进 `app/src/main/assets/public`。
- `dist/` 与 `android/app/src/main/assets/public` **都是 gitignored** → 构建链不产生需提交的产物，可在**所有合并完成后**统一跑一次。

**两条链的 base 不同，且顺序不能反**：

| 目标 | base | 命令 |
|---|---|---|
| 安卓壳（`https://localhost`） | `/`（默认） | `npm run web:build` → `npx cap sync android` |
| GitHub Pages | `/stzb-battle-sim/` | `bash scripts/deploy-gh-pages.sh` |

先 `cap sync` 再构建 Pages 版；顺序反了会把 Pages 前缀的前端拷进安卓壳（资源全 404）。

### ★ 2026-09-19 线上事故：git-bash 的 MSYS 路径转换会改写 `--base`

从 git-bash 跑 `npx vite build --base=/stzb-battle-sim/` 时，**MSYS 把该参数当成 POSIX 路径转换成 Windows 路径**，vite 实际收到 `C:/Program Files/Git/stzb-battle-sim/` → `dist/index.html` 里资源写成 `/Program Files/Git/stzb-battle-sim/assets/...` → **线上全站 404**；而部署脚本是 `--force` 推送，直接覆盖掉上一版可用产物。

- 复现特征：`git show origin/gh-pages:index.html | grep assets` 看到 `/Program Files/Git/` 前缀。
- 脚本已修：`MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*'` + **产物自检**（`index.html` 未引用 `${BASE}/assets/` 就 `exit 1`，拒绝推送）。
- 应急修法：改用 PowerShell 直接 `npx vite build --base=/stzb-battle-sim/`（无 MSYS 转换），**推送前先验 `dist/index.html`**，再镜像进 `.gh-pages-work` 提交强推。
- 通用教训：**任何跨 git-bash/PowerShell 的构建参数，推送前都要验产物**；`--force` 推送没有任何回退保护。
