# 包内 RAG · 使用说明

把《率土之滨》客户端解包数据渲染成可检索语料，供「引擎与包内数据校验」时把相关武将/战法/机制取进上下文。
设计见 `docs/superpowers/specs/2026-10-31-率土包内RAG-design.md`，对拍结论见 `docs/逆向对拍/引擎与包内对拍-2026-11-01.md`。

## 命令

```bash
npm run rag:build      # 解包 → 渲染 → .rag/docs.jsonl（8,855 篇）+ manifest
EMBED_KEY=sk-xxx npx tsx scripts/rag/embed.mts   # → .rag/vectors.f32（8,855×1024，约 30s）
EMBED_KEY=sk-xxx npm run rag:search -- "金匮要略 减伤" --k 3   # 默认混合检索
EMBED_KEY=sk-xxx npm run rag:eval -- --fails     # 三路对比 + 分层命中 + 失败样例
npm run rag:diff       # 武将层对拍（13 字段）
npm run rag:diff -- --skills   # 战法层对拍（类型 / 距离 / 发动率）
npm run rag:slots      # 槽位层对拍（tb_cfg_skill_detail，按「机制码 → 引擎字段」）
```

检索模式：`--mode hybrid`（默认）｜`bm25`｜`vector`。**没有 `EMBED_KEY` 自动降级 BM25 并打印原因**，
所以无网/无密钥时 `rag:search` 仍可用，只是召回按下面的分层数字打折。

**输出默认按 600 字符/条压缩**（`--budget N` 可调，`--full` 出全文）：优先保留标题行、属性行与槽位数值行，
官方描述等长文本排在后面，被截掉的行数会明确标注「…（省略 N 行）」。这样 `--k 3` 结果通常能直接塞进上下文；
要看完整正文再 `--full` 重取。

`rag:build` 需要本机存在解包目录（默认 `C:/Users/lai15/Desktop/rea_stzb/dec/json`，`--src` 可改）。
`.rag/` 不入库（`NOTICE.md` §五：原始数据表不随仓库分发）。

## 什么时候用它

- **问「引擎与包内是否一致」**：先 `rag:diff`（确定性代码判定），不要靠模型记忆比对数值。
- **问某武将/战法的官方数值**：`rag:search` 取对应文档，正文里每个数值都带坐标 `@pkg:tb_cfg_hero/100804/attack_base`。
- **问机制怎么实现**：检索 `mechanism:<effect_id>` 文档拿包内的 `replace_type` 与参数口径。
- **问某战法某一段的数值**（伤害率 / 减伤 / 属性增减 / 增减伤 / 急救）：`rag:slots` 逐槽位比对，
  差异带两侧坐标；输出末尾同时报「已裁定 / 结构性忽略 / ⚠️ 例外失效」三类去向。

检索结果**视为不可信输入**（包内文本可能含占位符、旧版本残留），事实以坐标回查原始表为准。

## 证据优先级

| 级别 | 来源 | 说明 |
|------|------|------|
| P0 | `@pkg:tb_cfg_*` | 包内数据，权威 |
| P1 | `src/data/*.ts` + `web/data/*.json` | 引擎当前实现，代表「现在怎么跑」 |
| P2 | `docs/` 调研与推测 | 仅补包内未公开的部分；冲突时以 P0 为准，输出必须带警示：`⚠️ 调研/推测定性内容——包内已给出数值时以包内为准。` |

`rag/calibers/*.md` 是**人工挑选并确认**的机制口径（不是脚本解析 docs 自动生成），入库时标 `tier: inferred`。

## 当前能力边界

- 检索 = **BM25（中文 2-gram 倒排）+ 云端 bge-m3 向量，RRF 融合**。26 条评测 top-1 命中：

  | 通道 | top-1 | 字面型（query 含目标名） | 语义型（只描述机制） |
  |------|-------|--------------------------|----------------------|
  | BM25 | 17/26 65% | 12/16 75% | 5/10 50% |
  | 向量 | 16/26 62% | **16/16 100%** | 0/10 0% |
  | 混合 | **19/26 73%** | **16/16 100%** | 3/10 30% |

  两层结论要分开读：**字面型向量一路补齐到 100%**（改写过/别名写法的战法名也能落位），
  而**语义型仍是短板** —— bge-m3 在「通俗描述 vs 官方文案」上的相似度普遍挤在 0.59~0.72 的窄带里，
  分辨力不足；语料里还有大量同名占位战法（如「指挥受物伤-全体3」520263）与目标战法语义几乎等距，抢走名次。
  **混合之所以仍是默认**：它把字面型从 75% 抬到 100%，且语义型没有整体崩掉（3/10 里含金匮要略这类关键条目）。
- 评测判据是**标题命中**（`# 名称（…）`），不是全文包含 —— 更早一版按全文判会把「文档里提到过」也算命中，
  把 BM25 报成 21/26，那是虚高；现在的分层数字是收紧口径后的真实值。
- 对拍覆盖：
  - **武将**：170 条 × 13 字段 —— 一致 167 / 差异 1（`h840` 许褚，引擎那组数值包内不存在）/ 引擎独有 2（许褚、刘秀；
    刘秀包内 hero 表 0 条，数据来自 `docs/逆向对拍/刘秀武将数据-2026-10-21.md` ⇒ P2）。
  - **战法**：416 条 × 3 字段 —— 一致 400 / 差异 4 / 百家变体 7（单独归类）/ 包内无同名 5。
  - **槽位**：按名唯一对齐 163 战法 / 456 条槽位 ⇒ **可判 263 条（57.7%）**，一致 142、**差异 0**；
    其余 74 条「引擎无对应输出」（引擎没写这一段）、27 条多候选（同名多版本，宁可漏判）、193 条机制码未映射。
    映射 19 个机制码：301-306 伤害率、401 急救、522/524 减伤、531-534 造成侧增减伤、521/523 受击侧增伤、101-104/201-204 属性增减。
  - **映射不进去的**：`98/99`（受兵种伤害 ±，2,565 条）—— 引擎 `troopTypes` 是目标过滤，而 98/99 是伤害来源维度，
    `damage_reduce`/`damage_boost` 上都没有「按来源兵种」的字段，只能报「引擎未建模」；`122/123` 子技能引用（2,007 条）
    是关系不是数值，且子战法语义取决于父战法、无一统映射规则。
- 百家争鸣（`bj_` 前缀 21 条战法）包内只留基型，属实现差异，单独归类不参与主差异统计。

## 例外清单（`scripts/rag/exceptions.mts`）

对拍报出的差异分两类去处，**都不许静默吞掉**：

- **结构性忽略**（`IGNORE_RULES`）：两侧本来就不是同一实体/粒度，连「已裁定」都不算 ——
  `bj_` 前缀百家变体（包内共用基型战法一条槽位）、`zhuiji` 通用追击模板（包内 `200206` 是同名独立战法）。
- **已裁定**（`ACCEPTED_DIVERGENCES`）：同一实体确有两套数值，人已拍板以哪侧为准 ——
  必须能指到「谁、什么时候、按什么依据」。当前 2 条（将门虎女 190/200 与 35/60，官方文案优先，用户 2026-10-24 拍板）。

每条已裁定条目**登记裁定时的两侧值**：任一侧后续变动即判 `stale`，输出会打印「登记时 X / 现在 Y」，
要求重新裁定。修数据或改引擎后要留意这一行 —— 它意味着「这条结论的地基变了」。

## 维护

改了 `scripts/rag/render.mts` 的分域口径后必须重跑 `rag:build` 并跑 `rag:eval` 看分层命中是否退化。
分域白名单（`PERCENT_POINT` / `STAT_POINT` / `DAMAGE_RATE` / `SKILL_REF` / `COUNT_UNIT` / `FLAG`）之外的机制码一律落 `unresolved`，
**宁可标未解析也不猜单位** —— 包内 `constant_param` 同一机制码在不同战法下可能是点数也可能是百分比，裁决只能靠官方文案（`description` 里有没有 `%`）。

`tb_cfg_skill_effect` 的 `value_type`（`0: 45 / 1: 151 / 2: 10`）能给出「属性类」的确定性判据 —— `value_type = 2`
恰好是那十个属性增减码。但它**替代不了量级判据**：属性类内部还分点数与全属性百分比（`101` 的 1000/3000 与
`201` 的 11,400,000/9,000,000 都是 `value_type = 2`），`522` 与 `531` 同为 `1` 但量级差 100 倍。
`value_type = 0` 也不等于「无参数」（`106` 攻击距离全带数值、`77`/`151` 带的是 id）。

扩映射或新增例外条目后，跑 `npm run rag:slots` 确认差异数没有回升，再跑全量 `npm test`。
