## 0. 一句话

主站顶栏只留一个跳转入口「AI配将」；功能全部搬进**独立页**：**极简单栏为底**（顶栏 / 对话区 / 输入区），顶栏最左的开关把**左侧栏**拉开即**工作台**（当前阵容 / 功能按键 / 最近一轮），设置等**不再常驻**页面——一律按键 + 按需面板；API key 只存在于「设置」弹窗里。


> 分区编号沿旧稿：4.2/4.3 的「横条」形态已并入 P1 左侧栏（见 §17），因此上表 P1 只有一条。

**边界（写进实现纪律）**

- 配将编辑**不回独立页**：独立页只能「读当前阵容 + 应用方案写回」；要改加点/红度/兵种 → 回主站（摘要条给「在主站编辑 ↗」）。
- 依赖共享：两边共用 `localStorage` 的配将配置与顾问键（`dsh-advisor-settings-v1` / `-session-v1` / `-profile-v1` / `-box-v1` / `-cache-v1`），独立页刷新不丢上下文。
- 独立页可深链：`advisor.html?q=<提问>` 直接开一轮（主站若要放"带问题跳转"的入口，无需改页面）。

## 6. 设置入口与设置弹窗

**入口三处，同一个弹窗同一把键**（`dsh-advisor-settings-v1`）：

1. 主站顶栏右侧 `⚙ 设置`；
2. 独立页顶栏 `⚙ 设置`；
3. 独立页 P4 成本行右侧「设置」（模型名旁，给"咦，模型在哪换"的人）。

**弹窗规格**：复用 `.modal` 骨架（遮罩 `rgba(10,8,5,.62)`、`radius 8px`、`--panel` 底、`m-head/m-body/m-foot`），宽 `min(620px, 92vw)`，标题「设置」+ 右上 `×`。

| 分组 | 字段 | 说明文案 |
|---|---|---|
| ① 模型接入 | 接口地址 / 模型 / 密钥（`password` + 显示切换） + `测试连接` | 「密钥只存在本机浏览器，直连厂商；本页不发往任何服务器」 |
| ② 额度与确认 | 调用次数上限 / 场次上限 / 词元上限；`长搜索先问我` + 阈值 | 「超过阈值先报价再跑」 |
| ③ 我的 box | 严格模式开关（与 P5-a 同源） | 「只在 box 内检索；方案里出现没有的将法会被拒收」 |
| ④ 数据 | 清空跑批缓存 / 清空当前会话 / 清空偏好档案（危险区，绯红描边） | 各自标出对应 localStorage 键名 |
| ⑤ 调试 | `干跑（不联网）` | 「链路完全一样，不花 token」 |

**纪律**：独立页主界面**零** key 相关控件（需求 ③）；未配 key 时不在页面里塞表单，而是对话区顶部一条引导条：「还没配模型 → 打开设置」，点开即这个弹窗（对应设计文档 §8 的错误处理口径）。

## 7. 对话 UI 的呈现方式

参照物：`@deepseek-ai/dsh-client-ui-chat` + `@deepseek-ai/dsh-client-ui-conversation`（本机 `dsh-tauri/dependencies/dsh/node_modules/@deepseek-ai/`）。**借的是语法，不是皮肤**。

| 借 | 不借 |
|---|---|
| 轮次即语义单元（用户输入 → 过程 → 结论），过程可折叠 | 系统提示词行、上下文注入行等调试行（顾问不需要） |
| 工具调用压成一行（turn-process folding，简洁模式） | 多 View 标签栏 / 轨迹视图切换 |
| 常驻 composer + Enter/Shift+Enter/Ctrl+Enter 投递语义 + 运行中主按钮位变 Stop | Lexical 富文本编辑器、@ 引用 chip、斜杠命令菜单 |
| 已完成轮次页脚 hover/聚焦才显操作（复制 / 重试） | 轮次轨道（turn rail）与阅读位置恢复 |
| 空态 EmptyHero + 建议提问 | 上下文占用圆环（顾问的"占用"是预算，用成本行表达） |
| Esc Esc 停止、贴底跟随 + 「回到底部」 | QueueDock（顾问一轮一答，不做排队队列） |

### 7.1 轮次结构（一个"问"= 一个 turn）

```
┌ 你 ──────────────────────────────────────────────── 右对齐气泡（最大 76%）
│ 「换一个前锋，伤害期望拉满」
├ 过程行（折叠）  ▸ 已执行 3 个工具 · 8,062 场 · 57s   ← 默认收起，一行；进行中原地刷新
│   └ 展开：① 读配将区（本地，0 场） ② optimize_mates 前锋位 · 粗筛 1,240 场
│            ③ optimize_both 交替 2 轮 · 6,822 场   每条带状态点：进行中/完成/被拒(橙)
├ 助手正文（markdown，15px/1.7，数字用 --gold-bright）
├ 证据清单（虚线框）：#1 前锋位组合粗筛 · 1,240 场 / #2 …
├ 方案卡 ×N（§7.3）
└ 页脚（hover 才显）：复制 · 重试这一轮 · 14:32
```

- 用户消息：右对齐、`--panel-2` 底 + 1px `--line`、`radius 8px`、左上角「你」12px `--text-dim`；不用头像图。
- 助手正文：**不加气泡**（全宽阅读列），只在段首用 11px `--gold` 行标「AI配将」；这是 DSH 的"助手消息即正文"语法，也为方案卡留出整宽。
- 进行中：轮次末尾一行「正在运行…」+ 3 点脉冲；停止后原地变「已停止 · 保留已收内容 + 重试这一轮」。

### 7.2 过程行（原「一行轨迹」升级）

- 收起态一行等宽字体（12px，`--gold-bright`，`--panel-2` 底、`--line` 边、`radius 4px`）：`▸ 已执行 3 个工具 · 8,062 场 · 57s`；进行中前缀换成脉冲点。
- 展开态逐条：工具中文名 + 关键入参摘要 + 场次/耗时 + 状态点（`--gold` 进行中 / `--text-dim` 完成 / `--orange` 被拒）。
- 保持既有纪律：**工具调用不刷屏**，只在此行内更新（`web/advisor/trace.ts` 口径不变）。

### 7.3 方案卡（`120%` 细节所在）

```
┌─ 方案卡 ───────────────────────────────────────────────
│ 一句话结论：前锋换孙策，三回合内伤害期望 +18%
│ 配置表  前锋 孙策  主·霸王渡江 ｜ 击势 ｜ 疾击其后
│         中军 … / 大营 …
│ 实测条  ████████▊░░  16,240 ± 420 · 40 场 · 与第 1 名并列
│ 对照     AI 搜索 6,822 场 15,980 ｜ 标准口径复算 16,240（差 1.6%，容差内）
│ [应用]（绯红主按钮） [对比当前配置]（文字按钮）   ⚠︎ 未验证（gate 未过 → 应用禁用）
└──────────────────────────────────────────────
```

- **实测条 = 本设计的签名细节**：横条按半宽画置信区间（`--gold` 实心段 + `--line-strong` 余段），末端 4px 刻度标「与第 1 名并列」；数字本身来自关 3 复算值（`--gold-bright`）。它是**数据的形状**，不是装饰——一眼看出"这条优势在不在噪声里"。
- 未验证态：卡片描边 `--orange` + 角标「未验证」，`应用` 禁用并在卡内一行写失败原因（不静默修，沿用设计文档 §8）。
- 应用后：卡内追一行「已应用到配将区 · 14:33」+ `去主站看 ↗`。

### 7.4 输入区交互（与 DSH 对齐）

`Enter` 发送 / `Shift+Enter` 换行 / `Ctrl+Enter` 也发送 / `Esc Esc`（500ms 内两次）停止；运行中主按钮位显示 `停止`，可发送内容时同位置变 `发送`；空草稿 + 运行中 → 按钮为 `停止`。

### 7.5 三态（原型里可切）

`空态`（hero + 建议提问 + 「先建档 box」次按钮）→ `对话中`（过程行脉冲 + 流式正文光标）→ `方案卡`（卡 + 页脚）。

## 11. 响应式与无障碍

- 断点：`1100`（侧栏从推挤改浮层 + 遮罩、面板全屏）/ `720`（顶栏精简、槽位卡占满一行、卡片堆叠）。
- 字号下限：正文 15px、标签/注释 ≥12px；正文对比度 `--text` on `--bg` ≈ 12:1（远超 4.5:1）。
- 键盘：面板/弹窗 `role="dialog" aria-modal="true"`、打开即聚焦首控件、`Esc` 关闭、焦点环用 `--gold-bright`（与主站 `:focus-visible` 一致）。
- 动效：面板 `transform .18s ease-out`；轮次新增 `opacity/translateY .15s`；**不使用 `transition: all`**；尊重 `prefers-reduced-motion`。

## 12. 验收标准（可执行）

**设计验收**
1. 独立页首屏（1440×900）**零输入控件**（顶栏 / 侧栏 / 对话 / 输入区四段一起断言）：key 只可能出现在设置弹窗里。
2. 功能按键 4 键 + 1 chip 全部有明确面板，无"点了没反应"。
3. 收起态：侧栏 rect 宽度 = 0（**含边框**），页面上看不到任何阵容/按键横条；输入区工具行可见、顶栏阵容行可见。
4. 展开态：侧栏 = 332px 且**推挤**（对话区确实变窄）；输入区工具行与顶栏阵容行自动收掉——同一套控件不同时出现。
5. 面板/弹窗互斥、关闭后对话滚动位置不变；**宽屏侧栏与面板可并存**（侧栏是推挤栏，不是浮层）。
6. 对话流三态（空 / 进行 / 方案卡）可复现；过程行默认收起、点击展开。
7. 色值只来自 `:root` 变量（裸 hex 只允许出现在 `:root` 块内）。

## 14. 设计自评与自检门（huashu-design 硬门）

**预发射 6 轴**（1-5，任何轴 <3 触发修订）：**P5 H4 E4 S5 R4 V5**（写在原型文件头注释里）

| 轴 | 判据 | 本设计的答案 |
|---|---|---|
| P 哲学 | 有立场吗 | 「对话是主角，功能退成按键」——页面身上只留对话，其余全部按需 |
| H 层级 | 2 秒分清主次 | 五级：顶栏(54) → 阵容条(66) → 按键条(44) → 对话(1fr) → 输入(≈96)；只有对话区滚 |
| E 执行 | 细节到位 | 颜色全变量、按键统一米黄/绯红标准、focus-visible 齐、区间条刻度对齐半宽 |
| S 特异性 | 是这个 brief 吗 | 实测区间条（金段=±半宽、刻度=第 1 名、盖住即标「并列」）只服务本产品 |
| R 克制 | 删干净了吗 | 空态与输入区的建议提问去重；成本只占一行；无装饰渐变、无多余图标 |
| V 多样性 | 与前作结构不同 | 相对主站三列配将台与旧抽屉是全新骨架；两态共用同一份 DOM，但收起/展开的**信息架构确实不同**（不是换色换字体） |

**slop-test 逐门**（huashu-design `references/slop-test-hs.md` 适用门）

| 门 | 结果 | 证据 |
|---|---|---|
| 无第二套皮肤 | ✓ | `:root` 变量逐条照抄 `web/styles.css:3-55` |
| 无紫渐变 / `background-clip:text` | ✓ | `grep -E "purple\|135deg"` 无命中 |
| 无纯黑纯白 | ✓ | 最暗 `--bg #12100f`、最亮 `--beige-hi #fff3da`（均为暖色相微 tint） |
| 无卡片左侧粗色条 | ✓ | 主战法用金色角标、严格模式用 chip、未验证用整卡描边 |
| 标题正体 | ✓ | `font-style` 无 italic（`grep` 无命中） |
| 不编造数据 | ✓ | 所有数字标「示例数据 · 非实测」，来源写清「工具返回 + 关 3 复算」 |
| 颜色走 token | ✓ | 裸 hex 只出现在 `:root`（grep 命中的 9 行全在 29–43 行）；其余为 rgba 中性遮罩/阴影 |
| 无 `transition: all` | ✓ | 只写具名属性（`background/border-color/color/opacity/transform`） |
| 无 emoji 功能图标 | ✓ | 功能图标 6 个，统一 16px / `stroke-width:1.5` / `currentColor` |
| 可读性底线 | ✓ | 正文 15px；按钮/标签 ≥12px；**仅元数据层 11px**（等级红度、成本行、时间戳——沿用主站 `.advisor-cost`/`.advisor-note` 既有口径） |

**假设清单（可反驳）**
1. 独立页承载全部顾问功能；主站不再保留抽屉（用户已选"独立 URL 页面"）。
2. 阵容**只读**，编辑回主站（用户已选"紧凑只读摘要条"，二轮改定后它住进左侧栏）。
3. 设置是一个**全局弹窗**，主站与独立页共用；主站入口用齿轮而非 `.nav-link`（保住 nav 计数断言）。
4. 成本行常驻（原抽屉口径），但只占 11px 一行。
5. 对话列宽上限 920px（DSH 是"≤900px 隐藏轮次轨道"，取同量级）。
6. **骨架 = 极简为底 + 左侧栏展开为工作台**（用户二轮口径）；侧栏状态是用户布局偏好，落 `dsh-advisor-rail-v1`。
7. 窄屏（≤1100px）侧栏改**浮层 + 遮罩**（推挤会把对话压死），并自带关闭钮（浮层会盖住顶栏开关）。

| `narrow-01-rail-overlay` / `narrow-02-min` | 窄屏侧栏浮层 + 遮罩 / 窄屏极简态 |

**渲染发现并修掉的真实缺陷（6 处）**——都是静态读代码看不出来的：

1. **`.hero` 类名撞车**：方案卡里武将名 `<span class="hero">` 被空态的 `.hero{display:flex;padding:52px;text-align:center}` 命中，配置表被撑成大空隙、名字居中跑偏 → 改名 `.gname`，并加断言（`display:inline` + 行高 <48px）。
2. **V2 栅格区冲突**：`p1`(rail) 与 `p2`(按键条) 共用 `grid-area:rail` 会叠在一起 → 拆出 `acts` 行。
3. **未配模型态白屏**：`state-nokey` 三个态块全隐藏 → 映射为「空态 + 引导条」。
4. **markdown 星号泄漏**：正文里 `**跑出来的数字**` 会原样显示 → 改 `<b>`，并加断言。
5. **10px 标签**：主战法角标 10px 低于可读性底线 → 12px；缩略图说明 10px → 12px。
6. **空态建议提问重复**（hero + 输入区各一份）→ 输入区 quick chips 在空态隐藏（去填充）。

另有 1 处原型自身问题（非设计问题）：窄屏下原型控制条会盖住设计稿 → 窄屏默认收起。

**二轮改定（极简为底 + 左侧栏）又在渲染复核中抓到 3 处缺陷，均已修**：

1. **`.body` 类名撞车**：新增的骨架容器 `.body` 与助手正文 `.msg-ai .body` 同名，全局 `display:flex` 把正文两段**并排**渲染 → 容器改名 `.shell`，并加断言（正文 `display:block` 且两段不共行）。
2. **收起态左侧留线**：`.rail` 宽 0 但 `border-right:1px` 仍在渲染（1px 竖线）；窄屏那条规则还额外挂了 `box-shadow`（一道淡影）→ 边线与投影只写在展开态，收起态断言必须等于 0。
3. **窄屏没有关闭入口**：浮层盖住了顶栏开关 → 侧栏自带关闭钮（仅 ≤1100px 显示），`Esc` 与点遮罩同样可关。

**本次验证踩到的两个环境事实（省下次的时间）**

1. `bash` 在本会话不可用（`ctx.shell.execute is not a function`，且 `sandbox_permissions` 报 "no sandboxing executor to escalate"）；截图改由 `pwsh` 执行同一脚本，结论等价。
2. `delivery_check` 传了 `url` 会让 `page-verify` **必然 FAIL**——这是预设 v1.23 的设计（不再自跑 headless smoke，视觉证据改由模型自测后放进 evidence）。正确用法：**省略 `url`**，在 evidence 里给 `kind=image/page/external` 且 `reviewed:true` 的视觉证据（工具描述里"省略 url 会 FAIL"那句已过期，以 `dsh-routing-suite/preset/router-standard/router-bootstrap.mjs:437-440` 的实现为准）。

> 会话内尝试把本设计作为 initiative 写入 Hindsight 失败（`401 Authentication failed: API key required`）——本项目记忆库当前未鉴权，故口径以本文件为准。

## 17. 二轮改定 · 骨架落地细则（极简为底 + 左侧栏 → 工作台）

> 本节**覆盖** §4.2 / §4.3 / §9 的旧形态（横条式阵容条 + 按键条、三变体），其余章节继续有效。

### 17.1 顶栏（P0）新增一个开关

- 位置：顶栏**最左**（率 logo 之前），用项目按键标准的小号图标钮（32×32，米黄实底 + `--beige-line` 描边），图标 = 侧栏轮廓（与其它功能图标同一套 1.5 stroke）。
- 语义：`aria-expanded` 跟随状态、`aria-controls="rail"`；hover 提亮一档；点一下切换两态。
- 顶栏其余元素不变：率 logo / AI配将 / 阵容一行（收起态才显示）/ 档案 chip / 严格 chip / 返回配将 / ⚙设置。

### 17.2 左侧栏（P1）两态规格

| 项 | 收起（默认 = 极简） | 展开（= 工作台） |
|---|---|---|
| 宽度 | `0`（**边框也一起收掉**） | `332px`（窄屏 `min(332px, 88vw)`） |
| 动效 | `width .2s ease-out`（**推挤**，不是覆盖） | 同 |
| 对话区 | 占满，阅读列 920px 居中 | 被推窄，阅读列仍以 920px 为上限 |
| 输入区工具行 | **显示**（功能的唯一入口） | 收起（避免与侧栏重复） |
| 顶栏「阵容一行」 | **显示** | 收起（阵容在侧栏里） |
| 边框 / 投影 | 无 | 右边线 `--line`；窄屏另加 `8px 0 24px` 投影 |

侧栏三段（自上而下）：

1. **当前阵容（只读）**：3 张竖排槽位卡（位置 / 武将 / 主战法角标 + 三战法 / 等级·红度）+「详情 ▾」展开四维 +「在主站编辑 ↗」。
2. **功能**：我的 box（角标 42/18）· 偏好档案（3 条）· 历史（2 轮）· 新会话 + 严格模式状态 chip。
3. **最近一轮**：工具数 · 场次 · 耗时 · token；搜索口径 vs 标准口径复算与差值；「示例数据」标注。

### 17.3 去重规则（一条铁律）

> **同一套控件，同一时刻只出现一处。** 侧栏展开 → 输入区工具行与顶栏阵容行自动收掉；侧栏收起 → 它们回来。
> 这样"展开"是**把散落的入口收进一个抽屉**，而不是"页面上多出一份同样的按钮"。

### 17.4 窄屏（≤1100px）

- 侧栏改 `position:fixed` **浮层 + 遮罩**（推挤会把对话压死）；宽度过渡、展开态边框与投影只在这一态给。
- 浮层会盖住顶栏开关 → 侧栏自带**关闭钮**（仅窄屏显示）；`Esc`、点遮罩同样可关。
- ≤720px：顶栏只留 开关 / logo / 标题 / 返回配将 / 齿轮；槽位卡各占一行。

### 17.5 状态与持久化

- `dsh-advisor-rail-v1 = '0' | '1'`（布局偏好，与设置键同族），刷新后保持。
- 收起态宽度断言必须为 **0（含边框）**——这是"页面上没有常驻信息"的可测判据。

### 17.6 二轮验收（已由 §15 的渲染断言覆盖）

- 侧栏 rect 宽度：收起 `0` / 展开 `332`；
- 展开是推挤：对话区宽度确实变小（1440 → 1108）；
- 展开态两处重复入口确实消失；开关 `aria-expanded` 同步；
- 刷新后仍展开；窄屏 = 浮层 + 遮罩，遮罩点击与关闭钮都能收起；
- 助手正文两段**纵向**排列（防骨架类名污染，见 §15 二轮缺陷 1）。

### 18.3 实装中发现并修掉的缺陷（5 处，都不是"设计没写清"，是写的时候真错了）

1. **设置弹窗关不掉**：`styles.css` 的 `.modal-mask` 默认就是 `display:flex`（不是靠 `.on` 显示），我的弹窗建出来后一直盖在页面上拦截点击 → `settings.css` 里补 `#advisor-settings-modal{display:none}` + `.on{display:flex}`。
2. **输入区被挤爆**：给 textarea 写了 `width:100%`，flex 下把「发送 / 取消」压成竖排 → 去掉宽度、加 `min-width:0`，按钮 `flex:0 0 auto`。
3. **换将自己跟自己互斥**：`applyPlanToTeam` 先查互斥再让位，导致"把同一个武将挪到另一个槽"被判成同名/SP 冲突 → **先让位再查互斥**（与主站 `onPickHero` 的实际顺序一致）。
4. **设置模块单例污染测试**：设置改成模块状态后，`localStorage.clear()` 不再能重置（上一条用例的阈值漏给下一条，14 项测试连带失败）→ 新增 `__resetSettings()`，`beforeEach` 里显式调用。
5. **弹窗里的值会过期**：关着的时候别处改了严格模式，再打开还是旧值 → `openSettingsPanel()` 打开时先与真源对齐（`paintModal()`）。

### 18.4 与设计的已知差异（如实记录）

- **过程行数据源**：明细直接读本轮 `inFlight.records` / 已落盘 `evidence`，没有为折叠单独存一份 trace。
- **侧栏「最近一轮」**是成本行的只读镜像（工具数 · 场次 · token），证据清单在「历史与证据」面板里，没做单独的「查看证据 ↓」跳转按钮。
