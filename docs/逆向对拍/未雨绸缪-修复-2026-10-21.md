# 未雨绸缪 修复记录（2026-10-21）

> 用户报障（m01313）两条：
> ①「未能使下一次造成谋略伤害的战法再次发动」；
> ②「战法描述缺一条：该战法造成的谋略伤害无视目标 x% 的谋略属性（受谋略属性影响），在战报中也没有体现」。

## 一、官方原文（9.2.2 热更覆盖层 `tb_cfg_skill` 200301）

```
下回合开始后，@2@回合内自身下一次造成策略伤害的主动战法发动后可再次发动一次（跳过准备回合），
造成原战法#subsk_210301_effect_01#%的伤害和恢复效果，
该战法造成的伤害无视目标#subsk_211301_effect_01#%的谋略属性（受谋略属性影响）
```

覆盖层写盘为 8 字节 XOR（`KEY=8e509fe8596791fb`，`plain[i]=enc[i]^KEY[i%8]`），解密后按 UTF-16LE 抽取。
覆盖层 detail 表 spec 漂移（`parse_rows` 抛 IndexError），改用「detail_id 的 `<i` 字节 + objHdr=43 + 字段合理性」定位：

| detail | effect_id | 关键字段 | 换算 |
|---|---|---|---|
| `21030101` | 111（额外参数） | `effect_param 21030102`、`init_effect_ratio 50`、`constant_param 50` | 再发动 = **50%** |
| `21130101` | 161（无视敌方属性） | `constant_param 18000`、`intel_param 30000` | 谋略 80 → **30.0%**，成长 **0.15/点** |
| `20030101` | 122（子技能容器） | `constant_param 210301` | 子技能族 |

机制 161 的量纲锚点 = 击势（`21186301` `constant_param 60000` ↔ 官方「无视敌方 60% 防御属性」）⇒ 除数 **1000**；
未雨绸缪 = `(18000 + 0.4×30000) / 1000 = 30.0%`，成长 `30000/200/1000 = 0.15/点`。

## 二、根因

`src/engine/action.ts` 的 `triggerRepeatStrategy()` 只用**顶层**判定与改写：

```ts
if (!outputs.some((o) => o.kind === 'strategy_damage')) return;   // 旧
```

全注册表递归扫描（`scripts/_scan_weiyu.mts`）：带策略伤害的主动战法 59 个，顶层 56，**伤害嵌在子树里的 3 个**：

- `guangwu_zhongxing`（光武中兴）：`random_pick.options` → `combo_tag.outputs` → `strategy_damage`
- `daoxing_xianzu`（道行险阻）：`schedule_strike.output` → `strategy_damage`
- `zhiren_daishi`（二类指挥，不在本路径）

⇒ 这三类「造成策略伤害的主动战法」永远不会再发动 —— 正是报障 ① 的现场。
（另有一半原因：机制 161 在引擎里其实早有 `ignoreStrategyPct/GrowthRate`，但数据侧没挂、战报与描述都没体现 ⇒ 报障 ②。）

## 六、二期（同日补修）：**本次发动**也要吃机制 161

> 用户口径：「该战法的效果应当使**本次发动和再次发动**都具备『无视 X% 谋略』；目前引擎只在再次发动时附加，
> 本次发动没有附加，属于缺陷」，并追加两条硬约束：**不重复叠加**、**不影响其他战法的正常结算**。

### 6.1 改动前的行为

机制 161 此前只在 `triggerRepeatStrategy()` 里注入 ⇒ 只有**再发动那一份**伤害带 `ignoreStrategy`；
首次发动沿用 `skill.output` 原样结算，目标谋略一点没折减（`tests/weiyu_choumou.test.ts` 里当时断言
`expect(first.ignoreStrategy).toBeUndefined()` —— 缺陷被写成了契约）。

### 6.2 本次改动

| 文件 | 内容 |
|---|---|

### 6.3 为什么要「结构递归」而不是继续枚举 kind

`_scan_weiyu_hooks.mts` 的结果：**光武中兴 9 段策略伤害里有 6 段在 `output[i].onHealCast.outputs`**（治疗结算时
再判定一次落雷 / 落石 / 绝水遏敌）。`onHealCast` 是**钩子配置对象、没有 `kind`**，任何 `switch (kind)` 的递归都会整块跳过。
只改枚举版本时，端到端统计能直接抓到：再次发动 194 段里仍有 **55 段**没有 `ignoreStrategy`。
改为「对象/数组结构递归 + `kind==='strategy_damage'` 处注入」后 → **194/194**。

「不重复叠加」落点：`injectIgnoreStrategyNode` 对每段判 `if (段上已有 ≥ 本次 pct) 原样返回`，**不做加算**；
标记消费改为 `statuses.filter(s => s.type !== 'repeat_strategy')`（旧实现只 `splice` 命中的一条，
两份同型标记会各触发一次再发动 = 效果叠加）。

## 七、三期（2026-10-22 补修）：触发判定要认得**子技能**与**谋略 DoT**

> 用户报障 ③（原话）：「未雨绸缪目前在面对『通过子技能造成谋略伤害』的战法时不会触发。
> 部分战法自身不直接造成谋略伤害，而是依赖子技能去造成谋略伤害；已知案例：十常侍的主战法、河内世泽。
> 按预期，子技能造成谋略伤害时应当能够触发未雨绸缪，但当前无法触发。」
> 口径确认：触发范围 = **委派子战法 + 谋略 DoT 一并算**（用户从两个选项中选了「一并算」）。

### 7.1 根因

`triggerRepeatStrategy()` 的判据是「本战法自有 output 树里有没有 `strategy_damage` 段」。
伤害既不在自有 output 里的战法因此全被漏判 —— 三个现场：

| 战法 | 伤害落在哪 | 本战法 output 里有什么 |
|---|---|---|
| 河内世泽 `heneishize` | `chainSkillPickGroups` 随机到的子战法（落雷 / 迷阵 / 溃堤 / 夹攻 + 伐谋 / 雀伏 / 火辎 / 毒泉） | 一段司马懿条件减伤 |
| 十常侍·乱政 `luanzheng` | **谋略 DoT 的跳伤**（恐慌 / 燃烧 / 妖术，`LUANZHENG_STATUSES` 数组随机 1 项） | 3 段 `inflict_status`，没有任何伤害段 |
| 连环计 `lianhuanji` | `chainSkills` 引用的伐谋 / 迷阵 / 落雷 | **`output: []`**（空数组） |

连带缺陷（同一处代码，会一起坏）：`executeSkillOutputs()` 里战法链 / 随机战法组被 `if (!outputs)` 把关，
而带标记的「本次发动」要传显式 `outputs`（注入机制 161）⇒ 标记在身时**整条战法链被跳过**，
河内世泽 / 连环计连原始伤害都不打。

### 7.2 改动

| 文件 | 内容 |
|---|---|
| `src/engine/action.ts` | ① 判据换成 `skillCanDealStrategyDamage(ctx, skill)`：自有输出树 / **谋略 DoT** / `chainSkills` + `chainSkillPickGroups` 递归解析被引用战法（`seen` 防环；`copyRandomActive` 奇门遁甲不计）。② `hasStrategyDamageInNode` 增补 `inflict_status` 分支 → `hasStrategyDotStatus()`（`STRATEGY_DOT_TYPES = panic / burning / sorcery / curse / ignite`；动摇 `unrest` 是物理 DoT，**排除**）。③ 再发动那趟把 0.5 缩放与机制 161 **贯穿到子战法链**：`RecastRewrite{factor, ignore}` 作为 `executeSkillOutputs` 第 8 参下传，`runChainSkills` / `runChainSkillPickGroups` 对被引用战法的输出先 `scaleRecastOutputs` 再结算。④ `scaleRecastNode` 的状态缩放进 `scaleStatusRates()`，修掉旧实现只读 `status.rate`、**`status` 为数组时整段跳过**（乱政的 10 选 1 池正是数组口径）。⑤ `repeatStrategyIgnoreOutputs` → `repeatStrategyRewrite`（同一判据，返回 factor 1 + 机制 161）。 |
| `tests/weiyu_choumou.test.ts` | 18 → **26 例**（新增 8 例，见 7.3） |

### 7.3 验证

新增 8 例（`未雨绸缪 · 子技能 / 谋略 DoT 触发（报障 ③）`）：

1. 河内世泽：总 `skill_cast` = 无标记时的 **2 倍**，其中 `recastRate === 0.5` 的恰好 = 无标记时的条数（**每个子战法只重放一次**），标记消费。
2. 河内世泽（合成战法组只含落雷，结果确定）：`damage` 1 → 2，两段都带 `ignoreStrategy.pct = 32`，第二段伤害更低。

### 7.5 已知边界（未改，登记）

- 机制 161「无视 X% 谋略」仍只作用于 `strategy_damage` 段，**不作用于 DoT**（DoT 状态没有该字段，跳伤按挂上时冻结的谋略结算）——与 §6.5 一致。
- 再发动对 DoT 是**新建一条 50% 实例**（DoT 不参与同源刷新），不会覆盖已有的同名 DoT。
- `copyRandomActive`（奇门遁甲「随机复制一个主动战法」）**不计入**「造成策略伤害」判据：复制对象在结算时才随机确定，判定阶段不可知。
- 未雨绸缪面对「只靠物理伤害 + 物理 DoT」的战法仍不触发（动摇 = 攻击 DoT）。
