# 公告栏维护（主站版本公告）

> 一句话：**公告数据只放一个地方 —— `web/changelog.ts`**。每次部署上线前在 `ANNOUNCEMENTS` **最前面加一条**，
> 主站版本号、底栏版本标记、公告栏标题、未读红点会自动跟着走；`web/changelog.test.ts` 会替你守住"漏写公告"。

## 一、数据存放位置（唯一真源）

| 项 | 位置 |
|---|---|
| 公告数据（版本 → 更新改动） | `web/changelog.ts` 的 `ANNOUNCEMENTS`（**版本倒序，第一条 = 当前版本**） |
| 当前主站版本 | 同文件的 `SITE_VERSION` = `ANNOUNCEMENTS[0].version`（**派生值，不要手改**） |
| 展示层（弹窗 + 未读逻辑） | `web/announcement.ts` |
| 入口 | `web/main.ts`：顶栏「公告」按钮 `[data-nav="notice"]` + 底栏版本标记 `#build-tag` |
| 样式 | `web/styles.css` 末尾「公告栏（更新公告）」一节：`.an-*` / `.nav-link.has-unread` / `button.build-tag` |
| 守门测试 | `web/changelog.test.ts`（数据）、`web/announcement.test.ts`（视图 + 主站接入） |
| 玩家状态 | 浏览器 localStorage 两个水位（每台设备各记一份，不进仓库）：`stzb_site_version_seen`（已读版本 → 红点依据）、`stzb_site_version_notified`（已弹窗提醒过的版本 → 还弹不弹） |

**为什么是 TS 模块而不是 `public/*.json`**：公告随代码提交、被 Vite 编译进带 hash 的产物 ——
离线（PWA / 安卓壳）可用、有类型与测试守门、不需要运行时请求，`public/sw.js` 的缓存策略也不用动；
而"上线"本来就要跑一次 `npm run web:build`，所以把公告写进代码里没有任何额外成本。

## 二、字段规范

```ts
{
  version: '1.1',            // 主版本.次版本（也允许 1.0.1 三段）
  date: '2026-10-05',        // 上线当天 YYYY-MM-DD
  title: '一句话主题',        // 版本块标题
  summary: '两三句导读',      // 可选
  groups: [
    { kind: '新增', items: ['玩家能看懂的一句话改动', '…'] },
    { kind: '修复', items: ['…'] },
  ],
}
```

| 字段 | 规则 |
|---|---|
| `version` | `主版本.次版本`（可三段）；**数组内唯一、严格倒序** |
| `date` | 上线当天，`YYYY-MM-DD`；越靠前的版本日期不得更早 |
| `title` | 一句话主题（如「首个公开版本」「宝物系统上线」） |
| `summary` | 可选，2~3 句导读 |
| `groups[].kind` | 只能是 **新增 / 优化 / 修复 / 调整 / 说明**（配色档：`.an-kind.add/polish/fix/tune/note`） |
| `groups[].items` | 每条至少一句完整的话；写**玩家视角**的"多了什么、能干什么"，不写内部字段名 / 代码路径 |

**版本号规则**：一次上线 **+0.1**（1.0 → 1.1 → 1.2 …）；整站大改版可以进 2.0。
每一次上线都必须有对应公告 —— 因为"首条公告的版本号"就是"当前主站版本号"，**没有公告就没有版本号**。

## 三、展示形式（玩家看到什么）

- **顶栏「公告」按钮 → 弹窗**：版本倒序列表；每条 = 版本号 + 主题 + 日期 + 分组条目；最新一条左侧绯红竖杠 + 「最新」角标；
  弹窗标题右侧显示「当前版本 v1.0」。弹窗骨架复用主站既有 `.modal-mask / .modal / .m-head / .m-close / .m-body`，配色只用主站变量。
- **未读红点**：**从没读过公告**（新装 / 清了存储）或**已读版本比当前版本旧**时，按钮右上角亮红点（`.nav-link.has-unread::after`）；
  打开公告栏就记账（写已读水位）→ 红点灭。
- **新版本自动弹一次**：弹窗水位落后于当前版本时（= 上线了新版本），玩家首次进入自动弹出公告；打开即记账，不会重复打扰。
- **首次运行（新玩家 / 清了存储）不弹窗，只留红点**（本次交付即此状态，等于"不触发发布"）：
  把弹窗水位直接推到当前版本，已读水位不写 —— 所以老玩家升级后照常被弹窗提醒，新玩家则看到一枚红点（点开即清）。
  想让新玩家一进来也弹一次最新公告，把 `web/changelog.ts` 的 `ANNOUNCE_ON_FIRST_RUN` 改成 `true` 即可 —— 这是唯一要改的地方。
- **部署回滚**（弹窗水位比当前版本新）：不弹旧公告，只把水位改回当前版本。
- 底栏版本标记（`v1.0`）**点得开公告栏**，它就是"当前版本号"。

> 为什么用两个水位：一个 key 表达不了"首启不弹窗、但红点要亮"——要么首启就弹（等于触发发布），
> 要么红点永远不亮；拆成"已读 / 已提醒"两个水位后，两个目标同时成立。

## 四、每次上线的写入步骤（照做）

1. **写公告**：打开 `web/changelog.ts`，在 `ANNOUNCEMENTS` **数组最前面**插入一条（版本号 = 上一条 +0.1）：

   ```ts
   {
     version: '1.1',
     date: '2026-10-05',
     title: '宝物锻造与兵种特性调整',
     summary: '本次主要改动一句话导读。',
     groups: [
       { kind: '新增', items: ['新增 XXX：一句话说清它能干什么。'] },
       { kind: '优化', items: ['XXX 现在会 ……'] },
       { kind: '修复', items: ['修好了 XXX 在 YYY 情况下不对的问题。'] },
     ],
   },
   ```

   ⚠️ 只改这一处：**不要**手改 `SITE_VERSION`、底栏 `BUILD_TAG`、任何别处的版本号（它们都从这条派生）。

2. **自检**（必须全绿）：

   ```bash
   npx vitest run web/changelog.test.ts web/announcement.test.ts   # 公告数据 + 公告栏视图
   npx tsc -p web --noEmit                                        # web 目录类型检查
   ```

   改动大时跑全量：`npm test`（含 golden 快照）。

3. **部署**（两条链的顺序不能反）：

   ```bash
   # ① 安卓壳：先用默认 base 构建，再同步进壳
   npm run web:build && npx cap sync android
   # ② GitHub Pages：脚本自带 base 前缀与产物自检
   bash scripts/deploy-gh-pages.sh
   ```

4. **上线后自检**：

   - 底栏版本标记显示**新版本号**；
   - 点「公告」，第一条就是本次公告（版本号 / 日期 / 条目都在）；
   - 老用户首次进入会自动弹一次。想在浏览器里复现自动弹窗，控制台执行下面两行后刷新
     （把 `1.0` 换成**上一个**版本号）：`localStorage.setItem('stzb_site_version_notified','1.0')` 与
     `localStorage.setItem('stzb_site_version_seen','1.0')`；
   - 想看「新装玩家」的样子（不弹窗 + 红点）：`localStorage.removeItem('stzb_site_version_seen')`
     与 `localStorage.removeItem('stzb_site_version_notified')` 后刷新。

## 五、回滚与常见问题

| 场景 | 做法 |
|---|---|
| 公告发早了 / 写错了要撤 | 把那条记录从 `ANNOUNCEMENTS` 删掉（或改回旧版本号）→ 重新部署；版本号自动回落，玩家端不会弹旧公告 |
| 只改文案，不加版本 | 直接改条目文字 → 重新部署；版本号不变 ⇒ 不触发红点与弹窗 |
| 玩家说"没看到公告" | 正常：公告只在**弹窗水位落后**时自动弹，平时要点顶栏「公告」；红点在"没读过 / 读过的版本更旧"时才亮 |
| 弹窗一直弹 | 不该发生：打开弹窗即写水位。若浏览器禁用了 localStorage（隐私模式），代码会退化为"只留红点、不弹窗"，不会反复弹 |
| 想让新玩家首启也看公告 | `web/changelog.ts` 的 `ANNOUNCE_ON_FIRST_RUN` 改 `true` |

## 六、可选：一条命令做视觉自检

改完公告栏（或上线前想确认没画歪），用自带脚本拍图 + `read_image` 看一眼：

```bash
npm run web                                                   # 另开一个终端起本地服务
node scripts/_announcement_shot.mjs http://localhost:5173/ ./shots
```

脚本用本机 headless Chrome/Edge（CDP，无需额外 npm 依赖）拍 5 张图，并打印四段状态：

| 图 | 看到什么 |
|---|---|
| `1-fresh-dot.png` | 新装状态：**不弹窗**，顶栏「公告」带红点，底栏版本标记 = 当前版本 |
| `1b-nav-zoom.png` | 顶栏右侧放大 3 倍 —— 像素级确认红点 |
| `2-panel.png` | 点开公告栏：版本 → 更新改动列表 |
| `3-autopopup.png` | 模拟"新版本上线"（两个水位压到上一版后重载）→ 自动弹窗 |
| `4-after-close.png` | 关闭弹窗后重载：不再自动弹 |

> 这张清单同时也是**交付验证**用的：`delivery_check` 不自己跑浏览器，页面视觉证据靠这条链
> （headless 截图 → `read_image` 复核 → 写进 evidence 的 `reviewed: true` 条目）。

## 七、与安卓打包号的区分（别混）

| 号 | 位置 | 含义 |
|---|---|---|
| **主站版本**（公告 / 底栏） | `web/changelog.ts` 的 `SITE_VERSION` | 玩家视角的第几版；由最新一条公告决定 |
| **安卓打包号** | `android/app/build.gradle` 的 `versionCode` / `versionName` | 装机 / 排包用；与主站版本互相独立，**不要同步手改** |

> 起因：早期底栏标记（`v2.1`）与 `versionName` 手改同步，两边容易漂移。现在底栏标记只认公告版本，
> `versionName` 只认打包 —— 各管一段，不会再出现"两处版本号对不上"。
