# 成长率规律速查（反推实读值用）

> 建立：2026-09-22。用途：**用户报「属性 → 游戏内实读值」，据此反推该战法段的 `growthRate`**。
> 权威公式出处：`dateyuan/谋略战法受谋略成长调研.md`（§1.2/§1.3）、`dateyuan/速度战法受速度成长调研.md`（§一/§6.1）。
> 工具：`node scripts/derive_growth_rate.mjs`（先跑工具，别手算）。

---

## 一、唯一公式

```
实际值 = roundRate( 基值 + 成长率 × (属性 − 80) )        # 属性 ≥ 80
实际值 = roundRate( 基值 × 0.4 + 基值 × 0.6 × 属性/80 )  # 属性 < 80（不参与反推）
```

- **基值 = 官方描述里的数值**，口径天然视为「属性 80 时的效果」（客户端配置表同样以 80 为锚点 ⇒ 描述值可直接当基值用）。
- **属性** = 施法者**生效属性**（含 buff/加点/红度/等级），不是面板裸值。谋略类=谋略、速度类=速度、攻击类=攻击、防御类=防御。
- **百分比类取整 `roundRate`：1% 粒度「八舍九入」**（小数 ≥ .9 才进位，否则舍去）：
  `rate = 72.61 → 72`、`84.79 → 84`、`91.0 → 91`。
  ⚠️ 与 `Math.round` / `floor` 都不同，用它反推才能复现实读。
- **属性点数类**（攻/防/谋/速 ±N 点）不套 1% 粒度，按 **0.1 位**记录（如 42.4、46.9）。
- 攻其不备的 2021 阈值表反证：raw 落在 n−0.1（72.5→4.9）时实读恰为 n ⇒ 八舍九入口径已被独立验证。

## 二、成长率的「硬件"约束：离散格 = 1/200

客户端配置表规则（`速度战法…调研.md` §6.1）：

```
效果值(属性 a) = constant_param + intel_param × a / 200
成长率/点     = intel_param / 200            # intel_param 为整数
```

- ⇒ **成长率是 0.005 的整数倍**（= n/200，n 为整数）。
- ⇒ 反推得到区间后，先看 0.005 的整数倍候选：`0.15 / 0.25 / 0.7 / 0.95 / 1.225 / 1.825 / 2.075 / 2.175 / 2.25 / 2.45 …`
- 仓库实测反例只有 3 个（均为「用户实读 / 手调」而非配置来源）：动如雷震 0.2532（配置 0.25）、当地止决 0.026（配置 5.2/200）… ⇒ **优先取 0.005 整数倍**，实测若咬死其它值再以实测为准。

## 三、数值规律（按效果分类，从仓库 122 个非零段统计）

> 「倍率」= 成长率 ÷ 基值。**只用于挑候选，不能当公式**——必须用实读点复算锁定。

| 效果类别 | 典型倍数（成长率/基值） | 常见实例 |
|---|---|---|
| **谋略伤害率**（策略攻击 / DoT / 妖术 / 恐慌 / 燃烧） | **≈ 1%（0.0086 ~ 0.0121）** | 众谋不懈 194→1.925、利兵谋胜 200→2.25、焰焚箕轸 119→1.3、白衣渡江 215→2.25、火势风威 221→2.45 |
| **恢复率 / 治疗** | 0.65% ~ 1.05%（锚点 0.75 与 1.0/1.175 均见） | 三军之众 151→1.575、皇裔流离 68→0.6、金匮要略 80→0.75、增援 198→2.1 |
| **增减伤 % · 家族 A（指挥增减伤）** | **≈ 0.5%** | 大赏三军/神兵天降/无心恋战/避其锋芒 30→0.15 |
| **增减伤 % · 家族 B（兵刃/受击类）** | 0.3% ~ 0.7% | 虎豹督军 50→0.25、魏武之泽 15→0.08、当地止决 8→0.026、诸葛锦囊减伤 35→0.25、其疾… |
| **属性点数类**（±N 点） | **≈ 0.4%（0.3%~0.5%）** | 列营守险 29.2→0.115、其疾如风 41→0.075、黄天御印 −26→0.2、魏武之世 −15%→0.045 |
| **固定不缩放** | **0** | 垒实迎击 200→0、青囊秘要 150→0、擅兵不寡 180→0、京观垒冢、诸葛锦囊增伤 14→0 |

**翻倍阈值 = 基值 ÷ 成长率**（合理性检验用，谋略伤害率常见 **88~136 点**）：
- 众谋不懈 194/1.925 ≈ 100.8；利兵谋胜 200/2.25 ≈ 88.9；焰焚箕轸 119/1.3 ≈ 91.5；动如雷震 40/0.2532 ≈ 158（速度类）。
- 单点实读时，先看 `(实读−基值)/(属性−80)` 落在哪个量级，再按上表挑「好看数」。

## 四、锚点自检（防用错属性）

- **锚点固定 80**。文档已验证：改用 100 会让三点实读交集为空（动如雷震实测）。
- 但 90 这类**邻近锚点**用纯高属性点无法排除 ⇒ **要钉死锚点，必须补一档低属性实读（属性 ≤ 120）**：
  该点数值 = 基值 + 成长率×20 左右，可直接读出基值量级。
- 属性 < 80 走 0.4/0.6 回落段，`derive_growth_rate.mjs` 会直接报警不出区间。

## 五、反推流程（拿到实读点照这个跑）

1. **问清 4 件事**：战法名 / **哪一段**（多段战法每段独立成长率）/ 缩放属性（谋略？速度？攻击？防御？）/ 实读时的**生效属性值**（含 buff）。
2. **填基值**：用官方描述里该段数值（= 属性 80 值）。若描述里没有系数，基值仍取描述值。
3. 跑工具：
   ```bash
   node scripts/derive_growth_rate.mjs --base <基值> --points "属性:实读,属性:实读"
   # 锚点交叉验证：node ... --anchor 100 --points ...（交集为空 ⇒ 锚点/基值错）
   # 候选复算：   node ... --check 0.005的整数倍
   ```
4. **看输出**：逐点区间 → 交集（宽度 > 0.01 说明点太少/跨度太窄，补点）→ 候选（含 基值/n 翻倍阈值候选）→ 复算表必须**逐点命中**。
5. **候选三选一优先级**：① 0.005 整数倍且落在同类别常见倍数内 → ② 与同战法其它段/同作者同批战法一致（如 0.7/0.13/0.15 推定先例）→ ③ 用户实读咬死的精确值。
6. 入库：`skills.ts` 填 `growthRate` → `listing.ts` 摘掉下架登记 → 写实测锁定用例（把实读点逐点断言）→ `tsc` + 全量 `npm test`。

## 六、已知冲突/例外（反推时别照抄倍率）

- **诸葛锦囊**：配置表给「增伤段 0.1」，实测谋略 373.1 仍是 14%（= 基值）⇒ 已按**固定 0** 入库；疑为「按大营谋略而非施法者谋略缩放」，待查。
- **桃园结义 0.925 vs 仓库 0.75、合流 1.325 vs 1.375、七步释嫌 1.4 vs 1.46**：配置表与用户补全/战报反推有 0.03~0.06 差异，逐项确认后再覆盖。
- **动如雷震**：配置 0.25，实测三点取 0.2532（第三点在 0.25 下差 1%）⇒ 保留实测值。
- **谋谟帷幄**：伤害应按**触发者自身谋略**缩放，引擎现按施法者（待改）。
- **同一次发动内自我叠加**：列营守险先挂谋略 buff 会抬高自身后续条目的谋略（是否改「发动瞬间快照」待定）。

## 七、属于「反推拿不到」的

- 机制缺失的段（如「先手」「重复触发」）——成长率补齐也上不了架，另见 `docs/下架武将清单.md`。
- 官方未给基值的段（如某些「恢复一定兵力」无恢复率）——先定基值再谈成长率。
