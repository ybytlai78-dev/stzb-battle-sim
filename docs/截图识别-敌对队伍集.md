# 截图识别 · 敌对队伍集（设计 + 操作手册）

> 2026-09-23 会话定稿。上位线：伤害分析工具 L4「多路径对手」的自动路径（见 `docs/会话交接-伤害分析工具.md` §5 待办 1）。
> 用户已拍板的口径：**识别由 AI 做（不走脚本认图标）**、**低于 40 级夹到 40**、**自由加点交给用户在面板上操作**、**两个文件夹（投放箱保持为空 + 归档）**。

## 一、目标与边界

**做**：把敌方阵容截图丢进投放箱 → AI 读图 → 固定 JSON → 脚本严格按库校验 → L4 对手池一键导入 → 直接批量模拟胜率。

**不做**（有意排除，别再当缺陷报）：
1. **模板匹配 / OCR 自动识别图标**——用户口径：脚本认图标容易错（二级兵种就是例子）。
2. **二级兵种解析**——图标表示，暂不识别。
3. **自由加点**——截图看不到，导入后由用户在 L4 配将面板的「加点·攻/谋」里手动分配（面板已有点数预算）。
4. **自动触发识别**——识别动作由对话里的 AI 执行（脚本不能看图）。

## 二、目录约定（两个文件夹）

```
战斗系统/敌对队伍集/                ← 投放箱：你只往这里丢图（识别后图会被移走 → 始终保持为空，只留 README）
  README.md
战斗系统/已识别敌对队伍集/           ← 归档：图片 + 同名 JSON + 汇总（我写）
  敌方-陈宫张宁吕蒙.png
  敌方-陈宫张宁吕蒙.json            ← 一张图一份识别结果（同名，人工好对照）
  队伍集.json                       ← 校验通过的汇总，L4 直接导入
  _errors.json                      ← 校验失败条目 + 原因（不静默丢弃）
```

- 流程：**丢图 → 说「扫图」→ 我识别 → 图片移动到归档目录 + 写同名 JSON**。
- **识别失败的图留在投放箱**：你一眼看出哪些没识别；我下次只扫投放箱，不会重复读已识别的旧图。
- git：`队伍集.json` / 单图 JSON **入库**（可追溯资产，含图片 sha256）；截图**不入库**（两边目录下 `*.png|*.jpg|*.jpeg|*.webp` 走 `.gitignore`）。
- 「投放箱为空」的判定 = 无图片文件（README 不算）。

## 三、识别 JSON schema（固定）

```jsonc
{
  "source": { "file": "敌方-陈宫张宁吕蒙.png", "sha256": "dae9ec3f…", "at": "2026-09-23" },
  "label": "敌方·陈宫张宁吕蒙",          // 对手池备注名
  "side": "enemy",                       // enemy | ally（截图选的是「敌方」还是「我方」页签）
  "slots": [
    {
      "position": "大营",                // 大营 | 中军 | 前锋
      "heroName": "陈宫",
      "heroId": "h443",                  // 校验后回填
      "level": 41,
      "troopTrait": "地利",              // 通用兵系特性；没有则 null
      "skillNames": ["迟智难酬", "神兵天降", "大赏三军"],   // 第 1 个 = 主战法
      "treasure": null,                  // 只在「稀世 + 名字在库」时非 null（见 §四-8）
      "treasureSeen": { "name": "白羽扇", "quality": "精品", "affix": null, "level": 9, "dropped": "非稀世" }
    }
    // 中军、前锋两个槽同结构；`levelClampedTo40: true` 由校验脚本在 level<40 时回填
  ],
  "unrecognized": ["二级兵种（图标）"]
}
```

要点：
- `skillNames[0]` **必须**是该武将的主战法——这条是识别质量的核心断言（见 §四-5）。
- `treasureSeen` 只为人工复核保留观察值（含丢弃原因）；**它不参与模拟**。
- 宝物右上角汉字数字 = 宝物等级（`玖` = 9，引擎 `TreasureLoadout.level`，缺省 10）。

**图1 识别结果（已核）**：大营 陈宫 `h443` Lv41 迟智难酬/神兵天降/大赏三军 地利｜中军 张宁 `h474` Lv41 黄天余音/众谋不懈/三术奇谋 地利｜前锋 吕蒙 `lvmeng` Lv42 白衣渡江/反计之策/道行险阻 地利；三件宝物 白羽扇·精品 → 雕翎扇·罕俦 → 白羽扇·精品（含词条 颖悟）**全部丢弃**。

**图2 识别结果（已核）**：大营 **SP太史慈** `h102003` Lv28 方阵掩杀/连战/疾击其后｜中军 曹植 `h672` Lv27 七步释嫌/焰焚箕轸/三术奇谋｜前锋 陆抗 `h574` Lv27 西陵克晋/青囊秘要/浑水摸鱼；无特性、无宝物、无二级兵种。

> ⚠️ **同名多版要按库内名记**：库里「太史慈 `taishici`（主战法 方阵突击）」与「**SP太史慈 `h102003`**（主战法 方阵掩杀）」是两条；截图里带 `SP` 角标的必须记 `SP太史慈`。
> 本会话第一版就把它记成了 `太史慈`，正是 §四-5 的**主战法断言**把它拦下来的（识别错 → 校验直接拒收，不进对手池）。

## 四、校验规则（确定性，无 AI）

校验实现一份、两处调用（**单实现防漂移**）：`web/teamScan.ts` 暴露纯函数 `validateScan(scan, tables)`，表由调用方注入——
- 浏览器：`web/heroes.ts`（`HERO_RECORDS`/`SLOTTED_HEROES`）+ `SKILL_REGISTRY` + `src/data/treasures.ts` + `FAMILY_TRAITS`
- 脚本：`web/data/heroes.json` + 同一批 TS 表（`src/data/skills.ts`、`src/data/treasures.ts`、`src/engine/secondaryTroop.ts`）

| # | 规则 | 违反时 |
|---|---|---|
| 1 | 位置恰好 大营/中军/前锋 各一个 | 报错 |
| 2 | 武将名**唯一命中** `heroes.json`（同名多版 → 列出候选让 AI 重判） | 报错 |
| 3 | 每个战法名命中 `SKILL_REGISTRY`（360 条），解析出 `skillIds` | 报错 |
| 4 | 战法**同队唯一**（率土规则：同一战法不能出现在任意两人） | 报错 |
| 5 | **`skillNames[0]` === 该武将 `mainSkillName`** | 报错 |
| 6 | 特性 ∈ 兵系通用特性池（`FAMILY_TRAITS` 并集）；与库内兵系不一致 → 仅 warning（例：张宁库内为步却带「地利」⇒ 推定做过兵种转换） | warning |
| 7 | 等级照录；**< 40 时入库夹到 40**（用户口径，`buildGeneral` 现状）并在 JSON 标 `levelClampedTo40: true` | 标注 |
| 8 | 宝物：`quality === '稀世'` **且**名字在 `TREASURES`（引擎稀世库 36 件，本就只含稀世）→ 收；否则整条丢弃并写 `dropped`；有词条时 `affix.name` 必须 ∈ 该宝物 `affixPool` 且 ∈ `AFFIXES`，`value` 默认取区间中点 `(min+max)/2` | 丢弃 / 报错 |

产物：
- `队伍集.json`：`[{ "name": "敌方·陈宫张宁吕蒙", "cfg": ViewCfg }]`（`ViewCfg` 见 `web/teamConfig.ts`）
- `_errors.json`：`[{ "file", "slot?", "rule", "message" }]`

## 五、L4 接入

1. **对手池新增「导入识别结果」入口**：粘贴 `队伍集.json`（或单条 JSON）；dev 下另给一个「从 `/已识别敌对队伍集/队伍集.json` 一键导入」（vite root 直接可 fetch，路径做 URL 编码）。
   `side` 只作记录：导入对手池时一律按对手处理；若该条 `side === 'ally'`（你方阵容），导入前提示确认一次。
2. **接口扩展**：`SlotCfg` 加可选 `traits?: GeneralTrait[]` 与 `treasure?: TreasureLoadout | null`；`generalsOf` 把这两项透传给 `buildGeneral` 的**第 9/10 参**（引擎侧 `traitStatBonus` / `traitCombatModifiers` / 宝物系统都已实现，**不改引擎**）。
3. **加点**：导入时一律 0 点，由用户在面板「加点·攻/谋」里分配（面板已有点数预算与上限）。
4. **等级**：`< 40` 夹到 40（现状不变），预览里标注「原图 Lv28 → 按 40 跑」。
5. **词条数值**：预览里可改，默认区间中点。

## 七、操作手册

**你（三步）**：① 把敌方阵容截图（选中「敌方」页签）丢进 `敌对队伍集/` ② 说一句「扫图」 ③ 在 L4 对手池点「导入识别结果」（粘贴或一键）。

**新会话（四步）**：① 读本文件 ② 扫 `敌对队伍集/` 的图片（`read_image`；小字看不清就用 `%TEMP%\crop.ps1` 裁剪放大，模式：`crop.ps1 <src> <dst> x y w h scale`）③ 按 §三 schema 写同名 JSON ④ `npx tsx scripts/scan_team.mts` 校验并汇总 → 移动图片+JSON 到 `已识别敌对队伍集/`。

## 八、未覆盖 / 风险

- **二级兵种不解析** → 兵种转换链缺失；但通用特性单独记（引擎按「特性 + 站位」算加成），模拟够用。
- **加点不可见** → 默认 0；对手实际加点会让模拟偏保守。
- **词条数值不可见** → 默认区间中点（可改），会有 ±区间一半的偏差。
- **等级 < 40 夹到 40** → 图2 那类小号队伍兵力/属性按 40 级算，会高估。
- **截图布局/皮肤差异** → AI 通道天然容忍；若日后固定布局，可再加自动裁剪预填（本期不做）。
- 识别质量本身依赖 AI：主战法断言（§四-5）是最有效的错判闸门——不符即拒收，不会把错配置烧进对手池。
