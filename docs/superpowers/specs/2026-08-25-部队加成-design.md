# Spec: 部队加成

## Objective

配将时根据本队阵营、称号、兵种给出属性加成；加成**不写进面板**，只在【部队加成】弹层展示，并在战斗准备阶段的**阵容**步写入战斗属性。准备回合固定为三段：阵容 → 兵种（本次留空）→ 战法。

成功标准：三吴队在弹层和战报【阵容】能看到每人四维 +10% 的点数；荀彧+郭嘉+贾诩同队全员谋略+32；三骑攻/速 +10%；上述加成进入 `effectiveStat` 后再结算魏武之世等战法百分比；详情页四维数字不变。

## Tech Stack

- 引擎：TypeScript（`src/engine`），确定性，随机只走 `rng.ts`
- Web：纯 DOM（`web/teamEditor.ts` / `web/main.ts` / `web/battleView.ts`）
- 测试：Vitest；golden：`tests/__snapshots__/golden.json`

## 已确认决策

1. 百分比各自对**面板**乘算，`Math.round` 后相加（阵营 10% 与骑兵 10% 攻互不合并再乘）。
2. 部队加成先写成点数，战法百分比打在「面板 + 部队加成 + 战法点数」上。
3. 独立 `formationBonus` 通道，不走 `inflictStatus`（避免同号增益冲突把阵营和兵种顶掉）。
4. 不修改 `general.attack` 等面板字段（避免「复用队伍」把加成当成加点）。
5. 红蓝标题行各有「部队加成」入口，只看本队。
6. 阵容加成后按新速度重排，战法阶段与 8 回合都用新顺序（同速仍前锋 > 中军 > 大营）。
7. 战报「始」同一页三段：【阵容】→【兵种】→【战法】。
8. `runBattle` 默认计算；直接拼 `ctx` 的单元测试缺省无加成（与伤兵死亡相同）。

## 判定规则

每队独立。空槽忽略。只统计本队实际上阵武将。

### 阵营加成

- 3 人同一 `faction`：三人四维各 +10%。
- 恰好 2 人同一 `faction`：**仅这两人**四维各 +8%；第三人（不同阵营）为 0。
- 三人三阵营或仅 1 人上阵：全员 0。
- 汉/晋/群与魏蜀吴同一套 2→8%、3→10%，无额外规则。

### 称号加成（本次仅魏之智）

表驱动，见 `src/data/titles.ts`：

| id | 名称 | 成员（须全部在本队） | 效果 |
|----|------|----------------------|------|
| `wei_zhi_zhi` | 魏之智 | 荀彧 `h24`、郭嘉 `h476`、贾诩 `h618` | 本队**全体**谋略 +32 |

缺任何一人则不触发。后续加称号只改表，不改判定引擎。

### 兵种加成

按 `troopType` 计数（`cavalry` / `infantry` / `archer`）：

| 兵种 | 2 人（仅这两人） | 3 人（全队） |
|------|------------------|--------------|
| 骑兵 | 攻击、速度 +5% | 攻击、速度 +10% |
| 步兵 | 攻击、防御 +5% | 攻击、防御 +10% |
| 弓兵 | 速度、防御 +5% | 速度、防御 +10% |

2 骑 + 1 步：只有两名骑兵获得 5% 攻/速；步兵无兵种加成。三种兵种各 1：全员 0。

## 数值公式

面板 = `General` 上已算好的四维（初始 + (L-1)×成长四舍五入 + 加点）。百分比**不再**乘加点后的「战法生效属性」。

对每一维 `stat`、每一个百分比来源 `p`（8/10/5/10）：

```
delta = Math.round(panel[stat] * p / 100)
```

同一武将：

```
formationBonus[stat] = Σ 阵营delta + Σ 兵种delta + Σ 称号点数
```

例：面板攻击 205，三吴三骑 → 阵营 `round(20.5)=21`，兵种 `21`，攻击合计 +42。

称号 +32 是点数，不经百分比。

## 数据模型

```ts
/** 四维部队加成（点数，已按面板换算） */
export interface FormationBonus {
  attack: number;
  defense: number;
  strategy: number;
  speed: number;
}

/** 单条可展示来源（弹层与战报【阵容】共用） */
export interface FormationBonusLine {
  unitId: string;
  category: 'faction' | 'title' | 'troop';
  /** 称号 id，仅 category==='title' */
  titleId?: string;
  titleName?: string;
  bonuses: FormationBonus;
}

export interface TroopBonusResult {
  /** unitId → 合计点数（写入 UnitState.formationBonus） */
  byUnit: Map<string, FormationBonus>;
  /** 全 0 的 line 不输出 */
  lines: FormationBonusLine[];
}
```

`UnitState` 增加可选字段 `formationBonus?: FormationBonus`。缺省视为四维 0。

`computeTroopBonuses(generals: General[]): TroopBonusResult` 放在 `src/engine/troopBonus.ts`，无 RNG、无战斗上下文。

## effectiveStat

```
base = general[kind]
flat = (formationBonus?.[kind] ?? 0) + 战法点数 buff
pct  = 战法百分比 buff 之和
eff  = base + flat
若 pct≠0：eff += round(|eff × pct / 100|) × sign(pct)
```

部队加成只进 `flat`，不进 `pct`。其疾如风 +41 与阵营速度%共存；魏武之世 -15% 打在含部队加成之后的 `eff` 上。

## 战斗准备流程

`runBattle` 在 `toUnitStates` 之后：

1. `computeTroopBonuses` 分别处理 `myTeam` / `enemyTeam`，写入每名 `unit.formationBonus`。
2. `turnOrder = buildTurnOrder(...)`（此时 `effectiveStat` 已含速度加成）。
3. `battle_start`：`turnOrder` 必须是加成后顺序；`seed` 不变。
4. 事件 `prep_phase { phase: 'formation' }`，再按下面顺序输出 `formation_bonus`：
   - 先我方后敌方；
   - 队内大营 → 中军 → 前锋；
   - 同一武将：阵营 → 称号 → 兵种；
   - 该来源四维全 0 则跳过。
5. `prep_phase { phase: 'troop' }`，无其它事件（转兵种未做）。
6. `prep_phase { phase: 'skill' }`，然后按新 `turnOrder`：一类指挥 → `battle_start` 被动。
7. `preparation_end`。

正式 8 回合仍用该 `turnOrder` 作为 `buildPriorityOrder` 的底序；每回合内速度比较继续走 `effectiveStat`（含部队加成）。

## 事件与战报

新增：

```ts
| { type: 'prep_phase'; phase: 'formation' | 'troop' | 'skill' }
| {
    type: 'formation_bonus';
    unitId: string;
    category: 'faction' | 'title' | 'troop';
    titleName?: string;
    bonuses: FormationBonus;
  }
```

**文本战报**（`report.ts`）在「准备阶段」标题下：

```
────────── 准备阶段 ──────────
> 出手顺序：id1 > id2 > ...
【阵容】
  → 太史慈 阵营加成：攻击+21 谋略+18 防御+12 速度+16
  → 荀彧 称号加成「魏之智」：谋略+32
【兵种】
  → 暂无效果
【战法】
  （既有指挥/被动/状态行）
> 准备阶段结束
```

无任何 `formation_bonus` 时，【阵容】写「无部队加成」。【兵种】本版本固定「暂无效果」。四维为 0 的维不打印（魏之智只打「谋略+32」）。

**Web 战报详情「始」**：按 `prep_phase` 切成三段标题【阵容】【兵种】【战法】；每段包含该标记之后、下一标记或 `preparation_end` 之前的事件。【阵容】段首必须渲染 `battle_start` 的出手顺序一行（加成后顺序）。`preparation_end` 不单独占一行。

golden：准备阶段结构变化 + 同阵营/同兵种固定集数值变化均为预期，测试通过后删除 `tests/__snapshots__/golden.json` 再跑以重录。

## Web UI

- `renderTeamPanel` 标题行：「部队加成」按钮在「清空本队」左侧（红蓝各一）。
- 点击打开弹层，三个页签：阵营加成 / 称号加成 / 兵种加成。数据来自当前该队 `SlotState` → `buildGeneral` 同款面板 → `computeTroopBonuses`。
- 页签过滤 `lines` 的 `category`。每行：头像、武将名、该来源非 0 维 `攻击+x 谋略+y 防御+s 速度+z`。
- 该页签无 line：`暂无阵营加成` / `暂无称号加成` / `暂无兵种加成`。
- 两人上阵、第三槽空：仍可出现 8% 阵营或 5% 兵种。
- 详情页与配将卡四维、兵力、加点均不加这笔。
- 红队弹层只用 `state.red`，蓝队只用 `state.blue`。

## Testing Strategy

文件 `tests/troop_bonus.test.ts`（计算不依赖 RNG；开战用例固定种子）：

1. 三同阵营：三人四维均为 panel 的 10%（round）。
2. 两同阵营 + 一异阵营：仅前两人 8%，第三人四维 0。
3. 三同骑：攻/速 10%，防御/谋略无兵种项。
4. 两骑一步：仅两骑 5% 攻/速。
5. 攻击 205 三吴三骑：攻击 +42（21+21），验证各自 round。
6. 魏之智三将：全员 strategy+32；换掉一人：全员称号 0。
7. `runBattle`：阵容事件存在；`turnOrder` 与加成后速度一致（构造一快一慢，慢方吃阵营速度后反超）。
8. 魏武之世：先加部队加成再打 -15%（对含加成后的攻击断言，允许 ±1 取整）。
9. 直接 `inflictStatus` 拼 ctx、无 `formationBonus`：行为与改前一致。

Web：`web/smoke.test.ts` 或同目录新测——红队入口不读取蓝队阵容；无加成页签文案。

## Boundaries

- **Always**：用 `faction` / `troopType` / 武将 `id`；加成只进 `formationBonus`；改引擎事件后重录 golden；`npx tsc --noEmit` + 相关 vitest 通过再收工。
- **Ask first**：新增称号、转兵种特性、改 8%/10%/5% 数值。
- **Never**：用战法状态模拟部队加成；改详情页面板数字；部分实现魏之智（缺人还加 +32）；引入 `Math.random`。
