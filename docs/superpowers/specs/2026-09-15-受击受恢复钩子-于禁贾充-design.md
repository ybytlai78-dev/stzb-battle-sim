# Spec: 受击 / 受恢复钩子（于禁补全 · 贾充录入）

日期：2026-09-15  
状态：已确认（2026-09-15）。实现计划：`docs/superpowers/plans/2026-09-15-受击受恢复钩子-于禁贾充.md`。

## Objective

扩展现有 `onHurt`，并增加对称的 `onHeal`，使「挨打 / 被奶」能按伤害类型与恢复量触发战法输出。本批只做两件事：

1. 补全于禁「当敌制决」的受击反制（现有减伤 50% 保持不变）。
2. 完整录入贾充「赏顺伐逆」（受恢复奶全体 + 受策略伤害反击）。

成功标准：于禁每次实际扣兵都给来源叠 taken 增伤（受防御 0.026/点）；贾充被奶则 75% 奶友军全体、吃策略伤害则 75% 反击来源；两条都不做部分实现。

## Tech Stack

- 测试：Vitest；`tests/main_skills_b2.test.ts`（于禁追加）+ 新文件（贾充）

## 已确认决策

1. 本批范围 = **于禁补全 + 贾充完整录入**。周泰 / 羊祜 / 卫子夫 / 陈到 / 张梁 / 孙坚不做。
2. 实现走做法 1：扩展现有 skill 级 `onHurt`，`recoverTroops` 旁加 `onHeal`。不抽通用事件总线，不改成状态监听。
3. 触发口径：凡 `applyDamage` **实际扣兵 > 0** 都算受击（普攻 / 主动 / 追击 / 指挥 / 分兵 / DoT / 诅咒 / 引燃）。贾充再按 `damageKind:'strategy'` 过滤；燃烧 / 妖术 / 恐慌 / 诅咒 / 引燃算策略。
4. 于禁反制成长率 **0.026/点（防御）**。公式与受谋略相同，属性换生效防御。
5. 贾充恢复率谋略成长 **0.325/点**（用户 2026-09-15 确认）；反击 180% 成长仍未知：**取基值**（`strategyScaled: false`、`growthRate: 0`）。文案仍写「受谋略属性影响」。
6. 贾充自己奶出去的恢复用 `resolvingHealHooks` 防重入，不再套自己。
7. 于禁反制无发动率、不限距离。贾充反击 `sourceMaxDistance: 5`。
8. 于禁阵亡后不再叠（不设 `retainAfterDeath`）；致死那一下仍叠（先 `onHurt` 再标阵亡，与典韦相同）。
9. 75% 走 `moraleTriggerRate`（被动生效几率）。于禁反制不走发动率判定、不发 `skill_trigger`（与必中 `onHurt` 一致）。
10. 恢复入口只有 `recoverTroops`：主动奶、持续急救、休整都算；恢复量 0 不算。
11. 钩子可自带 `output`，缺省仍用 `skill.output`（典韦 / 盲侯行为不变）。

## 引擎

### `applyDamage` 伤害类型

签名增加可选 `damageType?: 'physical' | 'strategy'`（缺省不传 = 两类 `onHurt` 都匹配，避免直构 ctx 的旧单元测试全改）。

各调用点必须传入：

| 来源 | `damageType` |
|------|----------------|
| 普攻 / `physical_damage` / 分兵 / `positional_physical_damage` | `physical` |
| `strategy_damage` / delayedOutput 策略 / DoT（燃烧妖术恐慌）/ 诅咒 / 引燃 | `strategy` |

`triggerOnHurt` 在实际扣兵 `> 0` 后调用，把 `damageType` 传下去。二次 `applyDamage`（反击）仍受现有 `resolvingHurtHooks` 保护，不递归。

### `OnHurtConfig` 增量

现有字段不动。新增：

- `damageKind?: 'physical' | 'strategy'`：缺省两类都吃。贾充写 `'strategy'`。
- `output?: SkillOutput[]`：缺省 `skill.output`。

`sourceMaxDistance` 已有。贾充用 5；于禁不设。

### `OnHealConfig`（新）

挂在 `PassiveSkill` 与 `CommandSkill` 上（本批只用被动）。

- `victim: 'self' | 'ally'`（本批 `'self'`）
- `rate?: number`（0~1，缺省 1）
- `applyTo: 'allies' | 'self'`（贾充 `'allies'` = 友军全体含自己）
- `output?: SkillOutput[]`

`recoverTroops` 在实际恢复 `> 0` 之后调用 `triggerOnHeal`。处理期间 `ctx.resolvingHealHooks = true`，内部再 `recoverTroops` 不再触发。75% 发 `skill_trigger`（含 `rate` / `baseRate` / `morale`）。

施法者阵亡且无 `retainAfterDeath` 则不触发（与 `onHurt` 相同）。贾充不设 `retainAfterDeath`。

### 防御缩放

`CreateStatus.damage_boost` 增加 `defenseScaled?: boolean`。`executeSkillOutputs` 里与现有 `strategyScaled` 并列：

```
sign = Math.sign(rate) || 1
scaled = roundRate(scaledValue(|rate|×100, growthRate, effectiveStat(caster, 'defense'))) / 100 × sign
```

于禁：基础 0.08、`growthRate: 0.026`。防御 80 → 8%；172 → `8 + 0.026×92 = 10.392` → 八舍九入 **10%**；212 → `8 + 0.026×132 = 11.432` → **11%**。

同战法重复施加走已有 sameSource **累加**（可无限叠）。

## 战法

### 当敌制决 `dangdi_zhijue`（补全）

现有：`phase:'round'` + `battleStartOnce` + 自身 `damage_reduce` 0.5 duration 999。不改减伤。

补：

- `range: 5`（官网；现为 1）
- `tags` 增加 `'damage_boost'`
- `onHurt: { victim: 'self', applyTo: 'source' }`
- 钩子 `output`：对来源 `inflict_status` `{ type:'damage_boost', rate:0.08, duration:999, direction:'taken', defenseScaled:true, growthRate:0.026 }`

准备阶段仍只跑 `skill.output`（减伤）。`onHurt` 准备阶段只登记。

### 赏顺伐逆 `shangshun_fani`（新）

```
type: 'passive'
timing: 'battle_start'
range: 5
triggerRate: 1
targetMode: 'self'
tags: ['heal', 'damage']
onHeal: {
  victim: 'self',
  rate: 0.75,
  applyTo: 'allies',
  output: [{ kind: 'heal', rate: 65, strategyScaled: true, growthRate: 0.325 }]
}
onHurt: {
  victim: 'self',
  rate: 0.75,
  damageKind: 'strategy',
  applyTo: 'source',
  sourceMaxDistance: 5,
  output: [{ kind: 'strategy_damage', rate: 180, strategyScaled: false, growthRate: 0 }]
}
output: []
```

恢复段 `strategyScaled: true`、`growthRate: 0.325`（已确认）。反击段 `strategyScaled: false`、`growthRate: 0` = **取基值**（结算不跑 `scaledValue`）。

`SKILL_ID_BY_NAME['赏顺伐逆'] = 'shangshun_fani'`。改映射后跑 `build_heroes_seed.mjs`（或等价改 `seed_heroes.sql` / `web/data/heroes.json`，以仓库现行灌数流程为准），使 `h708` 的 `mainSkillId` 非空。

## 测试口径

### 于禁（`main_skills_b2.test.ts` 追加）

原 4 条减伤断言保留。新增：

1. 受击后伤害来源身上有本战法 `damage_boost` taken；防御钉在 80 时 rate 为 0.08。
2. 连续两次受击 sameSource 累加（约 0.16，允许缩放后的精确值）。
3. DoT（策略）跳伤也叠。
4. 于禁已阵亡后再打来源，层数不再增加；致死那一下有叠。

确定性：用 `forceOnHurtRate` 同类手段不需要（于禁必中）。防御用 `level40(..., { defense: n })` 钉 80 或 172。

### 贾充（独立测试文件，至少 3 条主断言）

1. **装配**：`h708` 被动槽含 `shangshun_fani`。
2. **受奶**：强制 `onHeal.rate=1`，贾充 `recoverTroops` 一次后友军全体有 `heal` 事件，恢复率按 65% 基值；该次群体奶不产生第二轮 `onHeal`。
3. **受策略 / 不受攻击**：强制 `onHurt.rate=1`，策略伤害反击来源（180% 基值）；普攻不反击。补充：DoT 跳伤算策略、触发反击。
