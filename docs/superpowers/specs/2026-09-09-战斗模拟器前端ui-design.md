# Spec: 战斗模拟器前端 UI 高保真原型（2 套）

日期：2026-09-09  
状态：套2（三列配将台）已选定并经视觉验收。高保真原型：`design-demos/02-workbench.html`。生产落地见 `docs/superpowers/plans/2026-09-09-套2前端落地.md`。
套1 沙盘仅作对照，不落地。

## Objective

为现有《率土之滨》式战斗模拟器做 **2 套可点击的高保真 HTML 原型**（不是改 `web/` 生产代码）。覆盖主流程：**配将 → 开战 → 战报（简略 / 统计 / 详情）**。伤害测试实验室不做。

成功标准：

1. 两套骨架一眼能分清（沙盘 vs 三列工作台），配色与卡片语言相同。
2. 横屏手机（主）和桌面都能走完一局演示流程。
3. 双击或本地静态打开即可点，不依赖引擎 `runBattle`。
4. 子 agent 各自交付一个完整 HTML，父对话只验收。

## 产品与受众

- 名称：战斗模拟器（不放官方「率」商标图；不要冒充网易客户端）。
- 受众：玩家。气质：游戏客户端，沉浸优先。
- 内容：仓库真实武将名、站位、战法名；画像用 `public/portraits/`。
- 演示战报：一套冻结的「演示数据」，界面标注「演示战报」，禁止编造成营销指标（如「胜率提升 10×」）。

## 已确认决策

1. 范围 = 整站主流程；伤害实验室不做。
2. 玩家向，偏游戏客户端。
3. 配色跟用户提供的荣誉统计截图；骨架不跟那一页，也不照搬现有率土工具台（套2 只复用**操作模型**）。
4. 原型以**手机横屏**为主画布；桌面用现有宽屏量级（约 1440×900）。上线后两端都要有——原型里用视口切换演示，不做成两套互不相干的产品。
5. 竖屏只做可滚动降级说明，不当主设计。
6. 两套：套1 = 对阵沙盘；套2 = 三列配将台。
7. 两套 HTML **必须由子 agent 分别撰写**，避免占满父对话上下文。

## 视口

| 模式 | 画布 | 用途 |
|------|------|------|
| 横屏手机（默认） | **844×390** | 主设计、主截图 |
| 桌面 | **1440×900** | 加宽同一信息结构 |
| 竖屏 | 不画主稿 | 套1/套2 页脚用一句话说明「竖屏改为纵向滚动」即可 |

每个 HTML 右上（画布外）放视口切换：`横屏手机` / `桌面`。切换只改外壳尺寸与内部 layout modifier（`.vp-phone` / `.vp-desktop`），不换另一套骨架。

## 色板（唯一 token，禁止组件里写裸 hex）

从用户参考图锁定，全部经 `var(--color-*)` 引用：

```css
:root {
  --color-bg: #12100f;          /* 暖黑，禁 #000 */
  --color-surface: #1c1817;     /* 卡片 */
  --color-surface-2: #241f1d;
  --color-line: #3a3330;
  --color-text: #eeeae4;        /* 奶油主字，禁 #fff */
  --color-text-muted: #8a827c;
  --color-crimson: #8f2c2c;     /* 主按钮 / 红队 / 卡片底边 */
  --color-gold: #c49a36;        /* 分项：胜、高亮、阵营 */
  --color-green: #3a6b4a;       /* 分项：恢复 */
  --color-blue: #2a4a7c;        /* 蓝队 / 控制占比 */
  --font-display: "Noto Serif SC", "Source Han Serif SC", serif;
  --font-body: "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif;
  --radius: 8px;
  --card-accent: 2px solid var(--color-crimson); /* 卡片底边，不是左侧粗条 */
}
```

- 主 CTA：沉血红底 + 奶油字。
- 卡片：`--color-surface`，圆角 8px，**底边 2px 绯红**（参考图签名；禁止左侧粗色条）。
- 金 / 绿 / 蓝只做分项，不铺满背景、不用紫渐变、不用霓虹。
- 标题正体，不用斜体。

## 套1 · 对阵沙盘

**form 来自内容**：六将面对面站位就是这款游戏的视觉母题，页面结构等于战场。

### 配将（横屏）

- 顶栏：左「战斗模拟器」，右「战报」「战法」（浮层，不占沙盘）。
- 主区：红左蓝右。每边自上而下 **大营 → 中军 → 前锋**。中间窄轴：`VS` · 最多 8 回合。
- 空位：「点此上阵」。已上阵：画像 + 名 + 两个携带战法点。卡上不堆四维数字。
- 点空位：右侧滑出武将池。点已上阵：全屏详情（左画像，右等级/红度/加点/三战法）。
- 底栏：红士气 | **开始模拟** | 蓝士气。士气默认 120，可点调 80–140（纯 UI）。
- 部队加成：队名旁小芯片，点开浮层（可用静态「三蜀 · 战斗中生效」示意，不必接计算公式）。

### 配将（桌面）

沙盘仍居中、卡变大。武将池改为右侧**常驻窄列**（可加宽），不退化成「池子占满正中」。

### 战报（叠在沙盘上，不离开战场）

底栏改为：返回配将 / 复用队伍 / 再打一场。顶栏页签：简略 / 统计 / 详情。方位保持 **红左蓝右**。

- **简略**：中轴胜/负/平 + 回合；六卡换成残兵；兵力条三段；0 兵压暗。不要荣誉扇形仪表盘。
- **统计**：六张荣誉风数据卡（杀伤、恢复、普攻次数）。点将 → 右侧滑出该将普攻/主战法/两携带（次数·杀伤·恢复）。「详情」浮层：大营/中军/前锋面对面占比条。桌面：六卡并排，点将明细右侧常驻。
- **详情**：左 = 当前回合六人兵力（仍是沙盘站位）；右 = 事件流。上沿：上一回合 / 下一回合 / 自动播放。发动率只保留「谁对谁、当前几率」；增减伤一行净提升/降低，点击才出明细。

## 套2 · 三列配将台

**form 来自内容**：配将的日常操作是「两边槽 + 中间挑人」，骨架等于工作台。

### 配将

- 横屏与桌面都是 **左红 | 中武将池 | 右蓝**。每队自上而下大营 → 中军 → 前锋。
- 池子永远在正中（与套1的结构差）。支持搜索框（可只过滤演示名单）与阵营/兵种标签。
- 拖拽：空槽放入、已有则替换（原型可用 click 代替 drag，但桌面必须至少一种投放）。
- 槽位横屏：画像 + 名 + 三战法点。桌面：左画像右信息。
- 详情浮层与套1共用同一信息结构（不要两套各做各的详情）。
- 顶栏、士气、部队加成芯片、开始模拟：同套1语义。

### 战报（离开配将台，独立阅读页）

与现有「返回配将」心智一致。页签与口径同套1，骨架不同：

- **简略**：红左蓝右横排镜像 + 中轴胜负 + 三段兵力。桌面更疏。
- **统计（手机骨架跟率土「战法统计」图二；头像用生产端 `_s.jpg`）**：左侧窄栏切「武将统计 / 战法统计」。战法统计每行 = 站位竖签 + 圆/方头像卡（Lv、红度星）+ 四列（普攻 / 主战法 / 携带一 / 携带二：名、次数、杀伤、恢复；恢复绿色）。武将统计：头像 + 队内伤害/恢复/控制占比。桌面同一骨架加宽，禁止退回纯五列表格。
- **详情（骨架跟率土详细战报图三；事件口径跟 `web/battleView.ts`）**：左列 1–6 头像（出手顺序，选中描边+箭头）；中列按 `unit_act_start` 分组，组头 = 头像 + 【名】行动阶段 + 兵力；发动率主干、增减伤净行可点、准备阶段【阵容】【兵种】【战法】。右侧窄栏：详/简、上下、回合切换；保留上一/下一/自动播放语义。统计与详情都用头像，不用竖版全身卡。

## 共用组件（两套同一套皮肤）

| 组件 | 规则 |
|------|------|
| 顶栏 | 矮、无副标题堆砌；导航是文字不是一排 icon |
| 主按钮 | 绯红填充；次按钮 surface + hairline |
| 武将卡 | 底边绯红；阵亡态降低饱和 |
| 兵力条 | 三段：剩余 / 伤兵 / 阵亡，禁止单色骗满 |
| 详情浮层 | 横屏左右分栏；关闭有 × 与点击遮罩 |
| 战法格 | 品级用金/色点，不用 emoji 当图标 |
| Toast | 仅错误（见下）；成功开战直接切战报，不庆祝 |

## 异常与空态

| 情况 | 行为 |
|------|------|
| 红或蓝一队无人 | 点开始模拟 → 顶/底一句错误「红蓝两队都至少需要 1 名武将」，不切战报 |
| 武将池空搜索 | 「无匹配武将」，诚实空态，不放插画 |
| 战报历史浮层 | 可放 1 条演示记录；空时写「暂无战报」 |
| 画像缺失 | 灰底 + 姓名，不画卡通脸 |
| 同名互斥 | 点已在对队的武将 → 短提示「双方不能使用同一武将」（原型可简化为禁用该卡） |

不做：登录、账号、引擎报错栈、随机种子输入。

## 原型可交互范围（子 agent 必做 / 禁止）

**必做（可点通）：**

1. 视口切换（横屏 / 桌面）。
2. 点空位选将、点将开详情、关详情。
3. 开始模拟 → 战报三页签切换。
4. 返回配将、再打一场（回到配将且保留阵容）。
5. 统计点将出明细（套1）或横滑/表格（套2）。
6. 详情回合上一/下一（可用 2～3 个演示回合，不必 8 回合全文）。

**禁止：**

- 接入 `src/engine`、Vite、npm 依赖。
- 调用 `Math.random` 当战斗结果（结果冻结）。
- 伤害实验室、战法图鉴全库、真实加点计算。
- 紫渐变、emoji 功能图标、`transition: all`、Inter/Roboto 作标题。

每个 HTML 为**单文件**（inline CSS + JS）。放在：

- `design-demos/01-sandbox.html` — 套1
- `design-demos/02-workbench.html` — 套2

可用相对路径引用 `../public/portraits/*.jpg`，不要 base64 整库画像。Google Fonts 允许外链 Noto Serif SC + Noto Sans SC。

HTML 头部注释必须包含：

```
/* Huashu · assumptions: … */
/* Huashu · pre-emit: P? H? E? S? R? V? */
/* Huashu · slop-test: N/N ✓ */
```

任何自评轴 < 3 须先改再交。

## 验收后锁定（套2 · 2026-09-09 晚）

以下覆盖上文「套2 战报」草稿，**以本段 + `design-demos/02-workbench.html` 为准**。

1. **选定骨架**：三列配将台（左红 | 中池 | 右蓝）。开战离开配将进独立战报页。不要做成沙盘。
2. **配色 token**：见上文 `:root`。另加品级：`--color-grade-s: #d989a0`（粉）、`--color-grade-a: #4a7ab0`（蓝）、`--color-grade-b: #4e8a62`（绿）。统计圆标、配将品级点、详情日志【战法】同色。
3. **头像**：统计/详情用 `avatarSrc`（`/portraits/{id}_s.jpg`），圆或小方、`object-fit:cover; object-position:50% 18%`。配将槽与简略战报可用竖版全身 `portraitSrc`。
4. **战报顶栏**：去掉「战斗模拟器」标题条。简略 / 统计 / 详情放到**底栏中段**；底栏左右仍是返回配将、复用队伍、再打一场。
5. **统计页**：左竖栏「武将统计 / 战法统计」（默认战法）。行顺序 **红大营 → 红中军 → 红前锋 → 蓝前锋 → 蓝中军 → 蓝大营**。每行：站位竖签 + `_s.jpg` 卡 + 四列（普攻/主战法/携带一/携带二）。口径：次数、杀伤、恢复（恢复绿色，可与杀伤同一行）。不要五列表格。武将统计：同序头像 + 伤害/恢复/控制占比条。
6. **详情页**：左 1–6 出手头像（点选滚动到行动组）；中按 `web/battleView.ts` 的 `unit_act_start` 分组日志；右详/简、回合、自动播放。发动率只保留主干句。增减伤净行可点。
7. **滚动条**：左侧头像列禁止出现横向拖拽条（`overflow-x:hidden`，选中箭头用 padding 躲开）。右侧日志条宽 4px、颜色贴近暖黑底。
8. **横屏密度**：统计行 `min-height` 足够露出头像与恢复数字，禁止六行被压叠裁切。
9. **伤害实验室**：本次不改交互与布局，只允许继承新 CSS token（若会串色）。
10. **引擎**：零改动。随机仍只走 `rng.ts`。
