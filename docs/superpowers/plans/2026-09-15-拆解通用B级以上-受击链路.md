### Task 3: 扣兵前钩子（`before_damage` / 当场规避 / `thisHitReduce`）

**Files:**
- Modify: `src/engine/action.ts`（`applyDamage` / `triggerOnHurt`）

**Interfaces:**
- Consumes: Task 1 的 `timing` / `thisHitReduce`；Task 2 的数组遍历与过滤
- Produces: `applyDamage` 扣兵前跑 `timing:'before_damage'`；成功 `grant_evasion` 则当场 `consumeEvasion`，发 `evasion_blocked`、本段不扣兵、不跑 after；`thisHitReduce` 改扣兵量；与 after 共用 `resolvingHurtHooks`

扣兵前顺序（spec）：

1. 若 `ctx.resolvingHurtHooks` 已 true（反击二次伤害）：跳过 before 与 after，仍扣兵 / 引燃 / 急救（与现网嵌套行为一致）。
2. 否则跑 before 钩子（可与 after 一样在 `triggerOnHurt` 内设 flag，或由 `applyDamage` 包一层；二次 `applyDamage` 两条都不跑）。
3. 钩子 `grant_evasion`：当场 `consumeEvasion(ctx, target, source?.general.id ?? '')`；成功则 `evasion_blocked`、**return（不扣兵、不 after）**。
4. 累加本段 `thisHitReduce`（健卒只有一条，按一次 `damage * (1 - rate)` 即可；多条则各自乘算）。
5. 扣兵（伤兵死亡拆分）。
6. 引燃 / 急救 / after `triggerOnHurt`。

`triggerOnHurt` 增加参数 `timing: 'before_damage' | 'after_damage' = 'after_damage'`。before 分支：判定成功后若 `cfg.thisHitReduce` 把它累加到返回值；若 output 含 `grant_evasion` 则 `applyOnHurtEffect` 后再 `consumeEvasion`。无 output 且仅 `thisHitReduce` 的钩子：发 `skill_trigger`（rate<1），不发 `skill_cast`。

空城 `rate:0.7`：`(cfg.rate ?? 1) < 1` 已发 `skill_trigger`。健卒减伤 `rate:0.5` 同样。
