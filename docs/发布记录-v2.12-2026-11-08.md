## 四、发布链口径（下次照做）

1. `git checkout -b release/vX.Y` → 提交 → `git push -u origin release/vX.Y`（main 有分支保护，直推会被 GH013 拒）。
2. `gh pr create --base main --head release/vX.Y` → `gh pr merge <n> --merge`。
3. `git checkout main && git pull --ff-only` → `bash scripts/deploy-gh-pages.sh`（内部会 `npx vite build --base=/stzb-battle-sim/` 并自检产物）。
4. `npx cap sync android` → `cd android && gradlew.bat --no-daemon assembleRelease`。
5. `gh release create vX.Y <apk> --title ... --notes ...`；README 的下载链接指向 `releases/latest`。

## 五、坑

- `shell=True` 走 cmd.exe 时不能带 `2>/dev/null`（cmd 不认，报「系统找不到指定的路径」）；用 `2>nul` 或改用 Python 的 glob / os。
- `delivery_check` 的 `file` 必须是 UTF-8 文本（APK 这类二进制会 FAIL 在 `encoding-utf8`）；`kind=external` 的 `target` 要填路径或命令，URL 只能写进 `result`。

## 六、v2.13 补发（黑屏事故）

**现象**：v2.12 的 APK 装上去纯黑屏（WebView 已加载、`document.readyState=complete`、`body.innerHTML.length=30`）。

**根因**：`scripts/deploy-gh-pages.sh` 用 `--base=/stzb-battle-sim/` 构建了 dist；紧接着 `npx cap sync android` 把这份
「GitHub Pages 口径」的产物打包进 APK，于是 WebView 去拉 `https://localhost/stzb-battle-sim/assets/main-*.js` ——
全部 404，页面永远空白。线上网页没问题（它本来就需要那个前缀），只有 APK 中招。

**证据**：APK 内 `assets/public/index.html` 的 script 为 `/stzb-battle-sim/assets/main-Da0UH1yn.js`；
真机 CDP 读到 `document.scripts[0].src = https://localhost/stzb-battle-sim/assets/main-Da0UH1yn.js`。

**修法**：新增 **`scripts/pack-apk.mjs`**（唯一打 APK 入口）：先删 `dist` 再用默认 base 重新构建 →
断言 `dist/index.html` 不含 `stzb-battle-sim` 且引用 `/assets/` → `cap sync` → `gradlew assembleRelease` →
再读 APK 内嵌 `index.html` 做同样断言 → 落 `dist-apk/stzb-battle-sim-<versionName>.apk` 并打印 sha256 与素材族计数。

**教训**：部署与打包**必须各自构建**，绝不能复用对方的 dist —— 两者 base 口径相反（Pages 要前缀，Capacitor 要裸 `/`）。
