## 四、发布链口径（下次照做）

1. `git checkout -b release/vX.Y` → 提交 → `git push -u origin release/vX.Y`（main 有分支保护，直推会被 GH013 拒）。
2. `gh pr create --base main --head release/vX.Y` → `gh pr merge <n> --merge`。
3. `git checkout main && git pull --ff-only` → `bash scripts/deploy-gh-pages.sh`（内部会 `npx vite build --base=/stzb-battle-sim/` 并自检产物）。
4. `npx cap sync android` → `cd android && gradlew.bat --no-daemon assembleRelease`。
5. `gh release create vX.Y <apk> --title ... --notes ...`；README 的下载链接指向 `releases/latest`。

## 五、坑

- `shell=True` 走 cmd.exe 时不能带 `2>/dev/null`（cmd 不认，报「系统找不到指定的路径」）；用 `2>nul` 或改用 Python 的 glob / os。
- `delivery_check` 的 `file` 必须是 UTF-8 文本（APK 这类二进制会 FAIL 在 `encoding-utf8`）；`kind=external` 的 `target` 要填路径或命令，URL 只能写进 `result`。
