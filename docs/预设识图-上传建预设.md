## 一、用户口径（2026-10-21，勿再动摇）

| 项 | 口径 |
|---|---|
| 入口位置 | 「热门预设」面板**标题行右端**（截图红框标注处，`×` 左边）＝ `上传图片` |

## 二、识别 JSON schema（模型固定产物）

```jsonc
{
  "side": "我方",                    // 截图选中的页签，仅记录
  "slots": [
    {
      "position": "大营",            // 大营 | 中军 | 前锋（截图左侧竖排标签）
      "heroName": "司马炎",          // 照抄卡面（带 SP / XP 前缀的一起抄）
      "redness": 5,                  // **只数红星**（红度）0~5；金/黄星是空位，看不清填 null
      "level": 50,                   // 只留痕（引擎按 40 级落库）
      "faction": "晋",               // 只用于同名多版消歧，看不清填 null
      "troopType": "步",
      "skillNames": ["谋议宏图", "白刃", "兵无常势"]   // 左→右三条，**第 1 条是主战法**
    }
  ],
  "unrecognized": ["看不清的原文片段"]
}
```

要点：
- `skillNames` 只抄**名字**：图标角上的 `S / A / B` 品级、「S2」赛季标都不是名字的一部分
  （真带上了也不会崩：`matchSkill` 的近似匹配会把 `汜水关S2` 落回 `汜水关`，有单测锁）。
- **`redness` = 红色星星的颗数，不是星数**。卡面右上角那排**永远是 5 颗**：红 = 已进的阶（红度），
  金/黄 = 还没进的空位；紧挨着的金色菱形「極」字标不是星。所以 5 红 = 5、1 红 4 金 = 1、全金 = 0。
  例（实测截图）：司马炎队三人全是红星 → 5/5/5；甘宁队只有甘宁第一颗是红 → **1/0/0**。
  ⚠️ 把「一排 5 颗」当红度会让全队白涨 5 档兵力与自由点（`troopCapacity` 含 `红度 × 200`），
  这是本条最容易错的一处，提示词里单独写了。

## 三、确定性对齐（`matchTeamScan`，无 AI）

模型只报名字，名字 → 库内 id 全部由代码定，纪律与 `web/advisor/box.ts` / `web/teamScan.ts` 同源
（复用 `matchHero` / `matchSkill` / `normalizeName`，不另立一套）：

| # | 规则 | 违反时 |
|---|---|---|
| 1 | 位置按 大营 / 中军 / 前锋 归位 | 缺 → 该槽留空 + warn；重复 → 取第一条 + error |
| 2 | 武将名同名唯一命中 → 定案；同名多版 → **列候选**（确认卡上点一下，`heroOverrides`） | 分不出 → 该槽留空 + error（**绝不猜**） |
| 3 | **主战法判定**：与武将库内 `mainSkillName` 同名的那条剔除，**绝不进 `extraSkillIds`** | 三条都对不上 → 按「第 1 条是主战法」处理 + warn |
| 4 | 其余两条走 `matchSkill`（排除武将主战法） | 认不出 / 是别将主战法 → 进 `unmatchedSkills` + warn（不静默丢） |
| 5 | 红度取**红星**颗数并夹到 0~5（越界夹断；`null` → 0 + warn） | warn |
| 6 | 等级恒 `SCAN_LEVEL = 40`；`rawLevel` 只留痕 | — |
| 7 | 同队战法唯一（含各将主战法） | warn（不拦落库） |

**为什么主战法必须剔除（写死在第 3 条）**：`buildGeneral` 已按武将 `mainSkillId` 自带挂一次主战法，
cfg 里再带一份会被引擎判定两次 —— 实测太史慈方阵突击 200 场：6.6 次 / 3524 伤害 vs 3.0 次 / 1551
（口径见 `docs/截图识别-敌对队伍集.md` §四）。

## 五、界面流程

1. 「热门预设」→ 标题行 `上传图片` → 弹窗；
2. 选图 / 拖图 / `Ctrl+V` 粘贴 → **自动开始识别**（一张图 = 一支队伍）；
3. 确认卡：三行（位置 / 头像 / 名字 / Lv.40 / 红度星 / 主战法+两个装配战法），
   下方一行问题清单（红字 = 要处理，灰字 = 提示），可**改预设名**、**切红队/蓝队**；
   同名多版给候选按钮，点一下就定案；
4. `存入我的预设` → `main.ts` 的 `saveScannedPreset` → `addPreset`（与手动保存同一条路径）→
   弹窗关闭、预设面板刷新并**自动选中**新条目；
5. 之后照旧：上场 / 重命名 / 删除（`#编号` 与手动预设完全等价）。

**模型来源**：与 AI 配将的「我的 box」识图**同一条通道**（`web/settings.ts` 里的 baseUrl / model / key，
`transport.once()` 非流式、图片先压长边 1600 / JPEG 0.85）。没配 key 且没勾「干跑」时，
弹窗页脚直接给「去设置里填模型」；勾了「干跑」则走示例回复，界面明确标注 **干跑示例（不是真读图）**。

## 七、未覆盖 / 风险

- **多队同图**：一张图只出一支队伍（游戏「阵容详情」一次也只显示一队）。多队请分次上传。
- **二级兵种 / 特性 / 宝物 / 加点**：按口径不识别（用户自己在配将区加）。
- **等级**：不识别，一律 40 级 —— 高分号（50 级）识别后会**偏低**，需要时在配将区调。
- **模型报价**：一次识别 = 一次多模态请求（走用户自己的 key，与 box 识图同价）。
- **识别质量**：主战法断言（§三-3）+ 同名多版候选是最有效的两道闸门；认不准的槽位留空而不是硬塞，
  因此「认不出来」时的症状是**留空 + 红字**，不是错的将。
