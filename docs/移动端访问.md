# 移动端访问说明（手机横屏）

## 一、手机访问方式

手机与电脑连接**同一个 Wi-Fi / 局域网**，然后在手机浏览器（建议 Chrome / Safari）打开：

```
http://<电脑局域网IP>:5173
```

电脑局域网 IP 查看方式（Windows）：

```
ipconfig        → 无线局域网适配器 WLAN → IPv4 地址（如 192.168.1.23）
```

### 方式 A：开发模式（推荐，改动即时生效）

```bash
npm run web:host     # 等价于 vite --host，监听 0.0.0.0
```

### 方式 B：构建产物（部署 / 分享）

```bash
npm run web:build    # 生成 dist/
npm run preview:host # 本地预览，等价于 vite preview --host，端口 4173
```

也可把 `dist/` 整个目录丢到任意静态服务器（Nginx、GitHub Pages 等）直接访问。

### 常见问题

- **手机打不开**：Windows 防火墙可能拦截了 Node。放行一次即可：
  设置 → 防火墙 → 允许应用通过防火墙 → 勾选 Node.js（专用网络）；
  或临时关闭防火墙测试。
- **端口被占用**：换端口启动 `npx vite --host --port 8080`，URL 同步改。
- **无法确定 IP**：用 `npm run web:host` 启动后，终端第一行会直接打印可访问的局域网地址。

## 二、横屏适配说明

- 页面为**固定单屏**设计（顶栏 / 配将三列 / 底栏），横屏下自动压缩：
  顶栏隐藏副标题、卡槽与武将卡片缩小、底栏参数紧凑、印章入口放大为触控目标。
- **刘海屏安全区**：已适配 `env(safe-area-inset-*)`，内容不会顶进刘海/底部横条。
- **iOS 细节**：输入框字号 ≥16px，聚焦时不会自动放大页面；双击缩放已禁用。
- **竖屏**：降级为整页纵向滚动，不会布局错乱（建议横屏使用以获得最佳体验）。

实现文件：`vite.config.ts`（host 监听）、`index.html`（viewport-fit=cover）、
`web/mobile.css`（全部移动端样式）、`web/main.ts`（引入 mobile.css）。

## 三、移动端界面重排（2026-11-05，手机专用）

手机横屏可用高度只有 390~430px，原先四处「固定占位」把内容挤到半屏以下。本次按界面逐块重排，
**全部只作用于手机**（触屏横屏 + 手机竖屏），桌面与平板（`pointer:fine` 或高度 ≥ 768）保持原样。

| 位置 | 改前 | 改后 |
|------|------|------|
| 配将页队头 | 「部队加成 / 保存预设 / 清空本队」+「显示下架武将」常驻一行 | 整行不渲染，高度还给两队面板与武将池（队别靠面板底边红/蓝色带区分） |
| 战法背包 | 搜索 + 品级 + 类别三行常驻，网格只剩一行 | 向下滚自动收起 → 留 32px 摘要条（当前筛选 + 数量 + 「筛选 ▾」）；向上滚或回顶自动展开 |
| 宝物选择 | 详情块常驻占半屏，网格只剩一行 | 详情收进贴底抽屉（44px 把手显示当前宝物名/类型/品级），点宝物展开、「收起」再折叠 |
| 战报详情 | 顶部结果条（平局 / 回合 / 双方残兵） | 不显示，直接从战报正文开始（胜负在「简略」页与底栏仍可见） |

实现文件：

- `web/mobileUi.ts`（新）：移动端判定 `MOBILE_UI_QUERY` / `isMobileUI()` / `onMobileUIChange()`，
  以及滚动收放 `bindScrollCollapse()`（捕获阶段收后代 `scroll`，rAF 合帧，回顶必展开）。
- `web/mobile-ui.css`（新）：本次全部新规则的唯一入口。**`web/mobile.css` 是 GBK 历史文件，不要再往里加规则**
  （转码会产生几千行无意义 diff），新规则一律写进 `mobile-ui.css`，它由 `web/main.ts` 在 `mobile.css` **之后**引入。
- 断点三处严格同源（`mobileUi.ts` / `mobile-ui.css` / `mobile.css`）：改一处必须三处同改，否则会出现
  「CSS 已收起但 JS 还在绑手势」的半死状态。

### 3.1 第二轮：A/B 六条的实装（同日，同一批改动）

第一轮把「大块占位」拿掉后，又针对剩下六处手感问题做了增量（同样只作用于手机）：

| 编号 | 位置 | 改前 | 改后 |
|------|------|------|------|
| A1 | 战法背包 | 收起态点「筛选 ▾」展开，手一滚又收起，像点坏了 | 搜索框聚焦期间**锁定展开**（`canCollapse: () => document.activeElement !== input`，`focus` 时强制展开）；失焦后恢复随滚动收放 |
| A2 | 宝物选择 | 抽屉收起时想继续必须先展开 | 把手右侧常驻「下一步」（放在 `[data-sheet-toggle]` 内部，`stopPropagation` 后直接进第②步） |
| A3 | 战报详情 | 右侧竖排「详/简/上/始」只有 22px 高；去掉顶栏后看不到胜负 | `.dv-rail button{min-height:32px}`；底栏 back 之后插入 `.dock-result`（「平局 · 8 回合」，title 带种子与双方残兵），桌面 `display:none` |
| B1 | 配将页筛选 | 「势力」「兵种」两行常驻 | 收成一行摘要（`势力 X · 兵种 Y` + 「筛选 ▾」），点开 `.hf-body` 展开；**不 redraw** 所以选完标签仍保持展开 |
| B2 | 顶栏 | 7 个按钮在手机上挤成一排 | 伤害测试 / 教程 / 公告 收进 `.nav-more` 下拉（「⋯ 更多」），其余舒展 |
| B3 | 战法卡 | 说明一律截成「主动 · 距离1 · …」 | 手机端改两行（`-webkit-line-clamp: 2`），距离与发动率看得全 |

**B2 的坑（别踩第二遍）**：`.nav-more-menu` 是 `position:absolute; right:0`，宽度按 shrink-to-fit 算，
而子项又是 `width:100%`（相对容器）→ 两者互相约束退到 min-content，中文被压成「一字一行」（实测 76px）。
必须给容器 `width:max-content` 且子项 `white-space:nowrap`（修后 121px）。回归脚本里有宽度守卫断言。

**A1 的语义**：`bindScrollCollapse` 的 `canCollapse` 只在「要收起」时被询问 —— 锁定期间**只许展开不许收起**，
所以聚焦时用户往回滚，筛选栏照样展开，不会「想看看已选条件却展不开」。

回归：`node scripts/_mobile_ui_20261105.mjs`（无头 Chrome，844×390@2 触屏 + 1440×900 桌面反证
+ **800×600 窄桌面反证**，47 项断言 + 13 张截图，产物在 `verify-shots/mobile-ui-20261105/`）。
窄桌面那一组专门证明「移动端规则挂在 `pointer:coarse` 上，不是窗口一窄就生效」。
