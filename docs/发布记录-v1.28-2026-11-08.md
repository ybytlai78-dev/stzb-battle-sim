## 一、本次内容

- 引擎 · 设施加成（四大营）：准备阶段新增 `facility` 阶段（排在 `formation` 之前），双方按四大营满级给全队四维 +20（静默生效，不发状态），四营特效各一条；战报开场新增「设施加成」段落，按阵营逐营写明谁拿到了什么。`BattleConfig.facilities` 缺省 `true`，可关。
- 引擎 · 白衣渡江（一类指挥延迟结算）：预存伤害不再按准备阶段的乘区冻结，改为**打出那一刻**现算增减伤与兵种相克（`storedDamage` 只留基值 `breakdown`）；`damage` 事件带上 `modifiers` / `damageRate`，战报补「伤害率 X%，此次伤害共计提升 / 降低 N%」。
- 引擎 · 持续伤害「挂上即定伤」：妖术 / 燃烧 / 恐慌 / 诅咒 / 引燃 / 动摇六类在**施加时**先叠持节镇西、再冻结增减伤，之后跳伤不重复叠层。避锐的消耗时点**故意未动**（留待验证标记）。
- 引擎 · 属性增减按百分比：修复战法 / 宝物的百分比属性增减被当成固定点数结算（`percent: true` 补齐 6 处；宝物 `attr()` 改按 `effect.unit` 判定）。
- 前端 · 战报显示延迟伤害倍率与增减伤来源、设施加成段落；公告栏合并为一条 1.28。
- 数据侧顺带落地：13 个战法 / 15 段成长率（`tb_cfg_skill_detail` 口径）与徽言龙凤接线用例。

## 四、发布链口径（下次照做）

1. `git checkout -b release/vX.Y` → 提交 → `git push -u origin release/vX.Y`（main 有分支保护，直推会被 GH013 拒）。
2. `gh pr create --base main --head release/vX.Y` → `gh pr merge <n> --merge`。
3. `git checkout main && git pull --ff-only`（本地 main 若没 upstream，先 `git branch --set-upstream-to=origin/main main`）→ `bash scripts/deploy-gh-pages.sh`（内部 `npx vite build --base=/stzb-battle-sim/` 并自检产物）。
4. **APK 只走 `node scripts/pack-apk.mjs --version <x.y>`**（唯一入口，自带两次 base 断言与 sha256 / 素材族打印）；不要手拼 `vite build && cap sync && gradlew`。
5. `gh release create <tag> <apk> --title … --notes-file …`；README 的下载链接指向 `releases/latest`。

## 五、坑

- **Pages CDN 滞后**：脚本推完 gh-pages 立刻 curl 线上仍是旧 HTML（`Cache-Control: max-age=600`），约 75 秒后才切到新产物。自检要么等一轮，要么用 `?n=<epoch>` 绕缓存并比对 assets hash，别急着判定部署失败。
- **首访「声明」遮罩挡住点击**：无头自检要先点 `.disclaimer-mask .m-close` 关掉，再点 `[data-nav="notice"]` 打开公告，否则 playwright 会一直等 click。
- **Release 命名口径两套号**：仓库既有 tag / release 全是**安卓包号**（v2.9…v2.14），而本次写入要求按**主站版本**建 `v1.28`。又因 v2.14 这个 tag 在本次之前已发布过（**同版本号的更早一次构建**，APK 同名 `stzb-battle-sim-2.14.apk`、sha256 `26fa70aa…`），若按 2.x 命名就必须删旧 tag，故本次按主站版本建 `v1.28`，`releases/latest` 已指向它。下次发版先定清「release 跟哪个号」，别再二选一。
- **简报里的 `web/announcement.test.ts` 不存在**：仓库只有 `web/changelog.test.ts`（公告数据守门）与 `web/announcement.ts`（渲染），别照抄不存在的测试名。
- **PowerShell 调 `npx` 只拿到 stderr**（UNDICI 警告），stdout / 退出码会丢；验证命令一律走 Git Bash 并显式 `echo exit=$?`。
- `delivery_check` 的 `file` 必须是 UTF-8 文本（APK 二进制会 FAIL 在 `encoding-utf8`）；`kind=external` 的 `target` 填路径或命令，URL 只能写进 `result`。
