# 北伐副本 · 副将机制（赛季模式，v1.21 / 2026-11-05）

> 顶栏「赛季」下拉把主站切成两种口径：**常规赛季**（= 引擎历史行为，一字不改）与**北伐副本**（新增副将）。
> 赛季差异**全部在 web 层合成**：`src/engine` 零改动，`tests/__snapshots__/golden.json` 不变。
> 包内证据（为什么是这套数值/这条槽位）见本文末「包内证据链」。

## 一、规则（用户 2026-11-05 口径）

| 项 | 口径 |
|----|------|
| 主将四维 | **主将 × 70% + 副将 × 30%**，逐项四舍五入；兵力（`maxTroops`）不变 |
| 副将主战法 | **占主将第二战法格** —— 判定顺序 `主将主战法 → 副将主战法 → 装配战法` |
| 装配战法上限 | 北伐下佩戴副将时 **2 → 1**（第二格被副将占）；未佩戴副将仍为 2（常规赛季恒为 2） |
| 副将等级 | **跟随主将等级**（40~50，同一 `level`） |
| 副将加点 | **独立预算**，按「该副将 + 红度 0 + 主将等级」算（`freePointBudget(副将, 0, 主将等级)`） |
| 副将红度 | 固定 **0**（不参与预算与面板） |

**副将合法性**（`deputyRejectReason`）：主将必须已上场、副将须在武将库内、**同阵营**、不能是同一张卡、不能与主将同名/SP 互斥。
**副将不生效的内容**：兵种（二级兵种/特性）、宝物、陈寿特性、拆解战法 —— 只有「四维面板」与「主战法」进战斗。
**队内唯一**：同一武将在本队只能出现一次（主将或副将都算），选择器与 `onSetDeputy` 双向拦。
**未实现**：副将不额外消耗统率（包内 `SubHeroLimit = 11` 的编队校验属出征层，模拟器无统率系统）。

## 二、交互

1. **顶栏「赛季」下拉**（`header.app .season-pick` → `#season-mode`）：`常规赛季` / `北伐副本`，落 `localStorage.stzb_season_mode`（`SEASON_KEY`），切换即重画配将区并弹提示。
2. **配将区**：带副将的槽位在武将卡 meta 上加「副将 X」，战法条里副将战法用虚线框与 `deputy` 角标区分。
3. **主将详情**（点槽位）：战法三格中 **第二格只读显示副将主战法**（点它 → 副将详情），块内小标「北伐副本 · 副将主战法占第二格」；
   未佩戴时显示「＋ 佩戴副将（北伐副本）」→ 副将选择器；已佩戴时给「更换副将 / 卸下副将」。
4. **副将选择器**：同阵营候选网格（`.hero-grid.deputy-grid`，搜索支持名字/拼音），**过滤队内成员与非法候选**。
5. **副将详情**（`openDeputyDetail`）：画像 +「副将」角标 + 兵种/攻击距离 + 「等级 跟随主将 Lv.N」+
  主战法格 + **独立加点**（`前值 » 合成值`，四维各自 `+/-/最大`）+「重置」+「卸下副将 / 完成」。
6. **切回常规赛季**：副将配置**保留**但不参与合成（弹提示说明），第二格恢复为可装配空位。
7. **挤占告知**：佩戴副将时若原本已有 2 个装配战法，弹「副将主战法占用第二战法格，已卸下「X」」。

## 三、实现地图

| 文件 | 职责 |
|------|------|
| `web/deputy.ts` | **唯一年赛季口径模块**：`SeasonMode` / `readSeasonMode` / `writeSeasonMode` / `DeputyState` / `emptyDeputy` / `mixStats`（70/30）/ `deputyBudget` / `deputyStatsAt` / `deputySkillId` / `equipLimit` / `deputyRejectReason` / `normalizeDeputy` / **`buildGeneralForSlot`** |
| `web/teamEditor.ts` | `SlotState.deputy?`；`EditorHandlers.season` / `onSetDeputy` / `onSetDeputyFreePoints` / `takenHeroIds`；`slottedSkills(slot, season)`；主将详情第二格与副将行；`openDeputyDetail` / `openDeputyPicker` |
| `web/main.ts` | 顶栏赛季下拉 + `seasonMode` 状态；`collectTeam` 走 `buildGeneralForSlot`；`onSetDeputy`（唯一性/拒因/裁装配战法/挤占提示）/`onSetDeputyFreePoints`；`onAddSkill` 用 `equipLimit`；`onSetLevel` 后用 `normalizeDeputy` 收缩副将加点；`takenHeroIds` |
| `web/presetStore.ts` | `normalizeSlot` 校正副将（`normalizeDeputy`）并把装配战法上限收到 `deputy ? 1 : 2` |
| `web/teamStore.ts` | `applyPlanToTeam` 写回时同样按 `deputy ? 1 : 2` 截断 |
| `web/changelog.ts` | 公告 1.21 条目（版本源） |
| `tests/deputy.test.ts` | 14 例（合成公式 / 等级跟随 / 加点独立 / 上限三态 / 战法顺序 / 常规赛季逐字段等值 / 拒因 / 预算 / 存档校正 / 两道防线） |

**合成函数是唯一入口**：

```ts
buildGeneralForSlot(slot, position, morale, season): General | null
// 1) buildGeneral(heroId, [], 加点, 站位, 红度, 等级, 士气, 二级兵种, 特性, 宝物, 陈寿)
// 2) classic 或未佩戴副将 → attachSkills(base, slot.extraSkillIds)
// 3) beifa + 副将 → attachSkills(base, [副将主战法]) 再 attachSkills(..., extraSkillIds.slice(0, equipLimit))
// 4) 四维替换为 mixStats(主将面板, 副将面板)，maxTroops 不动
```

⚠️ 新代码别再直接调 `buildGeneral` —— 一律经 `buildGeneralForSlot`，否则北伐队伍会静默丢掉副将。

## 五、包内证据链（为什么这么建模）

- 运行时字段：`Tenth.Data.Mt_hero.cs:309` `public int sub_hero_idu;` —— 每张卡一个副将槽。
- 编队校验：`Game.Core.decompiled.cs:12999` `public const int SubHeroLimit = 11;`（出征失败原因「副将超限」）。
- UI：`AppointSubHeroAnim` / `CardOperateAppointSubHeroView` / `SubHeroDetailTipsUI` / `SubHeroEnergyTipsUI` / `SubHeroLevelTipsUI` / `SubHeroReportTipsUI`。
- 缺环（如实登记）：**70%/30% 的合成公式与「占第二战法栏」的开关参数不在已导出的三张表**（`tb_cfg_hero` / `tb_cfg_skill` / `tb_cfg_skill_detail`），
  落在未反编译的 `Game.Data.GamePlay` 层；因此 70/30 与「占第二格」按**用户口径**实现，数值集中在
  `web/deputy.ts` 的 `DEPUTY_STAT_SHARE = 0.3`，将来拿到包内值只改一处。

## 六、边界

- 胜率实验室 / 伤害实验室 / 对手池 / 战报「复用队伍」仍按**常规赛季**口径（副将只影响主站配将区 → 出战）。
- 预设与队伍存档会**保留**副将配置（跨赛季不丢），但只有北伐赛季参与合成。
