# 验证报告：知己知彼「初始 0 层」+ 胜兵求战「友军不含自己」

日期：2026-10-30　分支：`feat/hero-mechanics`　工作区：`C:\Users\lai15\Desktop\战斗系统`

## 一、用户口径（原话，勿再动摇）

1. 「知己知彼初始应该是没有层数的，但是引擎中初始就有一层 8%」
2. 「胜兵求战的描述『任意友军施放主动战法』不包括其自身。目标为两个队友，我军群体才是我方三选二，友军是不包括自己的」

## 二、根因

| # | 症状 | 根因（改前代码事实） |
|---|------|---------------------|
| 1 | 知己知彼开打即有 8% | 我军侧 `allyDealStack` 在**准备阶段**给锁定友军挂 `caused` 8% 跟踪状态（`src/engine/action.ts` 原 1217-1229）；敌军侧走 `initialOutput` 两条 `taken` 8%（`src/data/skills.ts` 原 11826-11856）。两条都是「免费首层」 |
| 2 | 胜兵求战自己发动也叠层 | `triggerCastKindHooks` 里 `allyActiveCastStack` 分支未排除 `holder === actor`，注释还写着「含自己」 |

## 三、改动

- `src/engine/types.ts`：`allyDealStack`（单条 + 数组元素两种写法）新增 `initialLayers?: number`——缺省 `1` = 现行为；`0` = 准备阶段不挂状态、首层由首次匹配伤害判定施加。`allyActiveCastStack` 注释改为「不含自己」。
- `src/engine/action.ts`
  - 准备阶段循环加 `if ((cfg.initialLayers ?? 1) === 0) continue;`。
  - 重写 `triggerAllyDealStack`：新增第二条通路——`initialLayers: 0` 的轨按 `ctx.lockedCommands` 反查「该战法锁定的目标是否含本载体」；与原有的「按已挂状态回溯来源战法」共用 `seen`（键 `${skill.id}#${idx}`）去重，首层挂上后由状态通路接管，不会双叠。
  - `triggerCastKindHooks`：`if (kind === 'active' && skill.allyActiveCastStack && holder !== actor)`。
  - 顺带修掉类型别名分发问题：`DealStackElem<T> = T extends Array<infer E> ? E : T`（直接对联合别名做条件类型不分发）。
- `src/data/skills.ts`：知己知彼两条 `allyDealStack` 轨各 `initialLayers: 0`；整块 `initialOutput` 删除（敌军侧同样从 0 层起，靠 `onHurt` 60% 判定叠层）；胜兵求战注释改「不含自己」。
- 测试：`tests/ally_deal_stack_track.test.ts`（7 例，含初始 0 层端到端）、新建 `tests/shengbing_qiuzhan_ally.test.ts`（2 例）。
- 文档：`AGENTS.md` 的 `allyDealStack` 节、`docs/待补充机制清点.md:75`。
