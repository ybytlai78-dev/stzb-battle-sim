# 《率土之滨》A 级及以上「受速度影响」战法成长调研

> 与《谋略战法受谋略成长调研.md》同口径（1.1 / 1.2），只是把属性从**谋略**换成**速度**。
> 首个实测点：**动如雷震（公孙瓒）追击战法伤害提升**，用户 2026-09-16 游戏内实读三点。

## 一、公式口径

```
速度 ≥ 80：实际数值 = roundRate( 基值 + 成长率 × (速度 − 80) )
速度 < 80：实际数值 = roundRate( 基值 × 0.4 + (基值 × 0.6) × (速度 / 80) )
```

- 基值 = 官方描述里的数值（描述值按仓库口径视为「属性 80」时的效果）。
- 增减伤百分比按 **1% 粒度「八舍九入」**（`roundRate`：小数 ≥ .9 才进位），与受谋略类完全一致。
- 引擎实现：`src/engine/formulas.ts` 的 `scaledValue` / `roundRate`；`damage_boost`（`speedScaled: true`）取**施法者生效速度**。

## 二、实测反解：动如雷震（公孙瓒主战法，追击战法伤害提升 40%）

官方描述：`使我军群体追击战法发动率提升100.0%，追击战法伤害提升40.0%（受速度属性影响），持续1回合`
（网易技能库 id 200955）→ 基值 40 @ 速度 80。

| 速度（游戏内） | 追击增伤（游戏内实读） |
|---|---|
| 208.8 | **72%** |
| 256.9 | **84%** |
| 281.4 | **91%** |

**逐点反解成长率区间**（要求在 `roundRate` 下正好取到实读值）：

| 实读点 | 成立的成长率区间 |
|---|---|
| 208.8 → 72% | [0.24767, 0.25543) |
| 256.9 → 84% | [0.24816, 0.25382) |
| 281.4 → 91% | [0.25273, 0.25770) |
| **交集** | **[0.25273, 0.25382)** |

→ 采纳 **0.2532 / 点**（区间中点附近；等价 `40 / 158`，即「+158 速度使该效果翻倍」）。
复算：速度 208.8 → `40 + 0.2532×128.8 = 72.61 → 72`；256.9 → `84.79 → 84`；281.4 → `91.0 → 91`，三点全中。

**锚点交叉验证**（同一组数据换锚点是否也成立）：

| 假设锚点 | 是否与三点自洽 |
|---|---|
| 速度 80（仓库口径） | ✅ [0.25273, 0.25382) |
| 速度 100 | ❌ 第三点要求 ≥ 0.2932，与前两点上限 0.2861 冲突 |
| 速度 90 | ⚠️ 仍留窄缝 [0.26852, 0.26902)（未排除） |

> 结论：三点已否掉「锚点 100」，但**速度 90 这类邻近锚点无法用纯高速度点排除**。
> 要彻底钉死锚点/基值，需要一档**低速实读**（速度 ≤ 120，理想是 100 左右：该点数值 = 基值 + 成长率×20，直接读出基值量级）。

## 五、反解工具（推导一律先跑它，再检验合理性）

```bash
# 基值 + 若干「属性:实读值」点 → 逐点区间 / 交集 / 候选 / 复算校验
node scripts/derive_growth_rate.mjs --base 40 --points 208.8:72,256.9:84,281.4:91

# 换锚点做交叉验证（判错锚点会直接报「交集为空」）
node scripts/derive_growth_rate.mjs --base 40 --anchor 100 --points 208.8:72,256.9:84,281.4:91

# 指定候选值复算（入库前确认逐点命中）
node scripts/derive_growth_rate.mjs --base 40 --points 256.9:84,281.4:91 --check 0.2532
```

输出含：逐点反解区间 → 交集与宽度 → 区间内的「好看数」候选（含 `基值/N` 这类翻倍阈值候选）→ 复算校验表。
退出码 0 = 全部命中可用于入库，1 = 有未命中 / 交集为空（口径矛盾），2 = 参数错误。

**检验合理性**（拿到区间后必做）：

1. 交集非空且宽度合理（宽度 > 0.01 = 点太少或跨度太窄，补点收敛）。
2. **翻倍阈值** = 基值/成长率 是否落在同类战法的常见量级（谋略类伤害率多为 88–136 点翻倍）。
3. 若同时有低速点与高速点，检查线性是否成立（工程上先按线性落地，异常再查递减）。
4. 入库后写实测锁定用例（把实读点逐点断言进测试），防止后续改动悄悄漂移。

## 六、客户端配置表反解（2026-09-18 发现；攻其不备 0.02 的入库依据）

### 6.1 规则

官方客户端把每个战法效果拆成 `detail` 行，满级数值由两个字段决定：

```
效果值(属性 a) = constant_param + intel_param × a / 200     # 属性点数类（攻/防/谋/速/攻城 ±N）整体再 /100
成长率/点      = intel_param / 200
```

- `attri_type` = 缩放属性：**0 / 缺省 = 谋略**，`1` = 攻击，`4` = 速度（其余待确认）。
- `a` = 施法者**生效属性**；`a = 80` → 描述值（与仓库「基值@80」口径天然一致，可直接入库）。
- 旁证字段：`init_effect_ratio` = 1 级占满级比例（攻其不备 50 → 1 级描述 5.8% = 11.6%/2 ✓）、
  `value_add_max` = 叠加上限（攻其不备 5、兵贵神速 8 ✓）、`available_round` = 持续回合（10 = 常驻）。
- 数据源：GitHub `GRQ02200059/stzb_watcher` 客户端配置转储
  `astzb/battle-engine-android/src/main/resources/battle-config/skill_table.csv` + `skill_detail_table.csv`
  （官方 id 体系，攻其不备 = 200755）。

### 6.2 攻其不备 推导（三条独立来源互相吻合）

1. **旧表反解**（2021-03 知乎「十面埋伏」《攻其不备增伤效果提升阈值》，表为图片）：
   速度 72.5→5%、97.5→6% … 222.5→11%、247.5→12% … 497.5→22%（**每 25 速度 +1%**）
   → 旧公式 `2% + 0.04×速度`（速 80 = 5.2%、速 100 = 6%）。
   副产品：阈值落在 raw = n − 0.1（72.5 → 4.9、247.5 → 11.9）→ **独立验证引擎 `roundRate`「八舍九入」口径正确**。
2. **2024-06-19 平衡调整**（17173 转载）："原本 100 速度的单次叠伤 6%，调整后则是 12%"、"200 速度调整前后只相差 4%"
   → 新公式须同时满足 100→12%、200→14%（旧 10%），配合官方描述 11.6%@80 → `10% + 0.02×速度`。
   `derive_growth_rate.mjs --base 11.6 --points 100:12,200:14` 反解区间 [0.01917, 0.0275)，**0.02 为区间内唯一整候选**。
3. **客户端配置表**：攻其不备 detail `20075501 / 20075502`（受到攻击 / 受到策略攻击伤害提高）
   = `intel_param 4 / constant_param 10 / attri_type 4(速度) / value_add_max 5`
   → `10 + 4×80/200 = 11.6%` ✓、成长率 `4/200 = 0.02` ✓、叠 5 层 ✓。

**结论**：攻其不备 = `10% + 0.02×速度`，即 **基值 11.6%@速80、成长 0.02/点、每 50 速度 +1%**（叠满 5 层）。
新版阈值网格（八舍九入）：**95→12%、145→13%、195→14%、245→15%、295→16%…**（速度 200 = 14%）。

### 6.3 规则校验（用仓库已有已知值当标准答案，共 97 条）

| 结果 | 条数 | 说明 |
|---|---|---|
| ✅ 基值与成长率逐位命中 | **80** | 含大明州谋略输出表全部条目、§ 二已验证项、§ 七治疗项 |
| ≈ 仅差 ≤ 0.008 | 3 | 重整旗鼓 1.125/1.13、动如雷震 0.25/0.2532、魏武之泽 0.075/0.08 |
| ❌ 成长率不一致（基值一致） | 4 | 桃园结义 0.925/0.75、合流 1.325/1.375、七步释嫌 1.4/1.46、诸葛锦囊增伤 0.1/固定 0 |
| ❌ 基值不一致 | 6 | 密谋定蜀恐慌 143/115、黄天当立 180/176·97、帝临回光 69/76·59、破阵强袭 130/119 |
| ➖ 配置表无此战法 | 4 | 火辐、玄武炬流、全主诱异、不休（旧 / 下架战法） |

关键结论：**配置表基值与官方描述 100% 一致**——6 条「基值不一致」全是**文档侧数值过期 / OCR 误差**：
对照 `scripts/skill_extra.json` 官方描述，密谋定蜀恐慌 **143.0**、黄天当立妖术 **180.0**、帝临回光恐慌 **69.0**、
破阵强袭 **130.0**，均与配置表逐位相同（本仓库实现也按官方描述）。成长率命中率 **83/93（89%）**，
冲突项集中在「用户补全 / 战报反推」这类非机器来源。

**入库前三条校验**：① 基值与官方描述逐位对照；② 与已有实测 / 社区表对照；
③ 差异 > 0.01 或涉及 0（不缩放）时标注人工复核，不直接写库。

### 6.4 疑点（待复核，勿直接改）

1. **动如雷震**：配置 `intel 50 / const 20`（attri_type 4）→ 成长 **0.25**；仓库现按三点实读用 0.2532。
   第三点 281.4→91% 在 0.25 下算得 90.35 → 90（差 1）；要成立需 281.4 的**实际生效速度 ≈ 283.6+**。
   建议补一档低速实读（120 附近）定锚点。
2. **诸葛锦囊增伤段**：配置 `intel 20 / const 6` → **0.1**；仓库按实测记为「固定 0」（谋略 373.1 仍 14%）。
   疑为「按大营谋略而非施法者谋略缩放」，待查。
3. **低速段（属性 < 80）口径**：引擎 `scaledValue` 用 `基值×0.4 + 基值×0.6×(a/80)`，配置公式是全域线性。
   2021 表速度 72.5→5% 只有线性算得中（4.9→5 ✓；回落段 4.891→4 ✗）→ 倾向配置线性，属**引擎级**待定项。
4. 桃园结义 / 合流 / 七步释嫌 的成长率与仓库值差 0.03–0.06，需按 §6.3 流程逐项确认后再覆盖。
