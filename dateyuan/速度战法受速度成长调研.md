# 《率土之滨》A 级及以上「受速度影响」战法成长调研

> 与《谋略战法受谋略成长调研.md》同口径（1.1 / 1.2），只是把属性从**谋略**换成**速度**。
> 首个实测点：**动如雷震（公孙瓒）追击战法伤害提升**，用户 2026-09-16 游戏内实读三点。

## 一、公式口径

```
速度 ≥ 80：实际数值 = roundRate( 基值 + 成长率 × (速度 − 80) )
速度 < 80：实际数值 = roundRate( 基值 × 0.4 + (基值 × 0.6) × (速度 / 80) )
```

- 基值 = 官方描述里的数值（描述值按仓库口径视为「属性 80」时的效果）。
- 增减伤百分比按 **1% 粒度「八舍九入」**（`roundRate`：小数 ≥ .9 才进位），与受谋略类完全一致。
- 引擎实现：`src/engine/formulas.ts` 的 `scaledValue` / `roundRate`；`damage_boost`（`speedScaled: true`）取**施法者生效速度**。

## 二、实测反解：动如雷震（公孙瓒主战法，追击战法伤害提升 40%）

官方描述：`使我军群体追击战法发动率提升100.0%，追击战法伤害提升40.0%（受速度属性影响），持续1回合`
（网易技能库 id 200955）→ 基值 40 @ 速度 80。

| 速度（游戏内） | 追击增伤（游戏内实读） |
|---|---|
| 208.8 | **72%** |
| 256.9 | **84%** |
| 281.4 | **91%** |

**逐点反解成长率区间**（要求在 `roundRate` 下正好取到实读值）：

| 实读点 | 成立的成长率区间 |
|---|---|
| 208.8 → 72% | [0.24767, 0.25543) |
| 256.9 → 84% | [0.24816, 0.25382) |
| 281.4 → 91% | [0.25273, 0.25770) |
| **交集** | **[0.25273, 0.25382)** |

→ 采纳 **0.2532 / 点**（区间中点附近；等价 `40 / 158`，即「+158 速度使该效果翻倍」）。
复算：速度 208.8 → `40 + 0.2532×128.8 = 72.61 → 72`；256.9 → `84.79 → 84`；281.4 → `91.0 → 91`，三点全中。

**锚点交叉验证**（同一组数据换锚点是否也成立）：

| 假设锚点 | 是否与三点自洽 |
|---|---|
| 速度 80（仓库口径） | ✅ [0.25273, 0.25382) |
| 速度 100 | ❌ 第三点要求 ≥ 0.2932，与前两点上限 0.2861 冲突 |
| 速度 90 | ⚠️ 仍留窄缝 [0.26852, 0.26902)（未排除） |

> 结论：三点已否掉「锚点 100」，但**速度 90 这类邻近锚点无法用纯高速度点排除**。
> 要彻底钉死锚点/基值，需要一档**低速实读**（速度 ≤ 120，理想是 100 左右：该点数值 = 基值 + 成长率×20，直接读出基值量级）。

## 五、反解工具（推导一律先跑它，再检验合理性）

```bash
# 基值 + 若干「属性:实读值」点 → 逐点区间 / 交集 / 候选 / 复算校验
node scripts/derive_growth_rate.mjs --base 40 --points 208.8:72,256.9:84,281.4:91

# 换锚点做交叉验证（判错锚点会直接报「交集为空」）
node scripts/derive_growth_rate.mjs --base 40 --anchor 100 --points 208.8:72,256.9:84,281.4:91

# 指定候选值复算（入库前确认逐点命中）
node scripts/derive_growth_rate.mjs --base 40 --points 256.9:84,281.4:91 --check 0.2532
```

输出含：逐点反解区间 → 交集与宽度 → 区间内的「好看数」候选（含 `基值/N` 这类翻倍阈值候选）→ 复算校验表。
退出码 0 = 全部命中可用于入库，1 = 有未命中 / 交集为空（口径矛盾），2 = 参数错误。

**检验合理性**（拿到区间后必做）：

1. 交集非空且宽度合理（宽度 > 0.01 = 点太少或跨度太窄，补点收敛）。
2. **翻倍阈值** = 基值/成长率 是否落在同类战法的常见量级（谋略类伤害率多为 88–136 点翻倍）。
3. 若同时有低速点与高速点，检查线性是否成立（工程上先按线性落地，异常再查递减）。
4. 入库后写实测锁定用例（把实读点逐点断言进测试），防止后续改动悄悄漂移。
