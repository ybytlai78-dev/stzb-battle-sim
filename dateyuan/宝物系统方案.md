# 率土之滨 · 宝物系统实现方案（v0.1 · 待确认）

> 配套调研：`dateyuan/宝物系统调研.md`（官方数据 + 官方公告 + 档位表） 、`dateyuan/宝物数据.json`（38 件稀世 + 12 组词条）
> 图片：`public/gears/gear_{id}.jpg`（立绘）、`gear_{id}_s.jpg`（图标）——**只保留稀世**，精品/罕俦不录入

---

## 0. 已确认口径（用户 2026-09-21，勿再询问）

1. **词条数量不强行统一**：按官方数据，该宝物词条池有几条就是几条（6 或 7）。
2. **数值由玩家选**：战斗系统允许「具体宝物 + 具体词条 + 具体数值」，用于测试；蓝/粉/红只作为**便于理解的提示色**。
3. **宝物效果不与任何其他效果冲突**：纯提升、可叠加（不是引擎现行的"同类型取高替换/刷新"）。
4. **默认 10 级**：1→5 级强化**第 1 条**效果、5→10 级强化**第 2 条**效果、**第 3 条固定**；
   **官方数值 = 每次强化的增量**（证据见调研 §8.2），故默认 10 级下：
   `第1条 = 官方值 × 5`、`第2条 = 官方值 × 5`、`第3条 = 官方值 × 1`。

## 2. 数据层（`src/data/treasures.ts` + `src/types/treasure.ts`）

```ts
export type TreasureType = '刀' | '剑' | '长兵' | '弓' | '扇' | '其他';

/** 宝物自带特效（一/二/三阶） */
export interface TreasureEffectDef {
  slot: 1 | 2 | 3;
  name: string;                 // 官方词条名（如 稳固、不移、英才）
  desc: string;                 // 官方文案（原样，供 UI tooltip）
  unit: 'point' | 'percent' | 'round' | 'special';
  /** 每次强化增量（slot1/2）；slot1、slot2 最终值 = perLevel × 强化次数 */
  perLevel?: number;
  /** slot3 固定值 */
  fixed?: number;
  mechanic: string;             // 引擎机制 id（见 §3）
  params?: Record<string, unknown>;
}

export interface TreasureDef {
  id: number; name: string; type: TreasureType;
  icon: string; image: string;  // /gears/gear_{id}_s.jpg | /gears/gear_{id}.jpg
  effects: TreasureEffectDef[]; // 1~3 条（slot 升序）
  affixGroup: number;           // 1~12
  affixPool: string[];          // 6~7 个词条名
}

/** 锻造词条（跨宝物共享，按名去重 42 条） */
export interface AffixDef {
  name: string; desc: string;   // 官方文案（含 #min~max# 区间）
  min: number | string; max: number | string;
  /** 颜色提示（社区档位表；仅 UI 用，不限制取值） */
  hint?: { blueMax?: number; pinkMin?: number; pinkMax?: number; red?: number };
  mechanic: string; params?: Record<string, unknown>;
}

/** 武将身上的宝物载荷 */
export interface TreasureLoadout {
  treasureId: number;
  level: number;                // 默认 10
  affix?: { name: string; value: number };   // 锻造词条 + 玩家选定数值（区间内任意值）
}
```

数据来源即 `dateyuan/宝物数据.json`（脚本 `scripts/fetch_gear_data.mjs` 可重抓）。生成 `src/data/treasures.ts` 用一次性脚本，**不手抄**。

## 3. 机制映射（引擎落地清单）

### 3.1 直接复用现有机制（约 26 条词条 / 大部分特效）

| 机制 | 覆盖词条 |
|------|----------|
| 属性 buff（点数/百分比，正负分桶） | 骁锐 攻击、天资 谋略、稳固 防御、灵动 速度、英才 谋略+速度、强固/明镜 等 |
| `damage_boost`（可按攻击类型限定） | 陷阵(普攻)、无畏(追击)、至策(主动)、亢厉(主动+追击)、击虚、选锋、蓄锐、鸠佑、迅猛、勇猛、燮理 |
| `damage_reduce`（可按来源限定） | 坚忍(主动)、沉稳(指挥)、强韧(普攻)、不移/戒备(全)、安贞(受控时)、护主 |
| DoT / 战法伤害增伤 | 驱火(燃烧/火攻)、炫惑(恐慌/妖术)、睚眦、炎势 |
| 恢复类加成 | 仁心(造成恢复+)、抖擞/济世(受恢复+)、不懈 |
| 发动率加成 | 机敏、英勇、筹算、熟虑、善谋、奔袭（追击） |
| 洞察 / 连击 / 规避 | 清毅、再战、避险 |
| 无视防御 / 无视规避 | 破敌（`ignoresDefense`）、识破（`ignore_evasion`）、颖悟 |
| 指定目标/位置逻辑 | 逐胜(兵力最低)、奇袭(距离)、矜节/阵舞(女性限定)、阵舞(受控目标易伤) |

### 3.2 需要新增机制（按工作量分档）

**A 档（小，1 个字段/分支即可）**
1. **禁普攻**（艮止）：`Status` 加 `noAttack`，行动时跳过普攻与追击。
2. **免疫控制**（坚毅）：施加控制时按来源豁免（前 N 回合）。
3. **无视防御/谋略百分比**（破敌/颖悟）：`ignoresDefense` 扩为 `ignoreDefensePct`（0~1）。
4. **不触发反击**（强击）：`retaliate` 触发前查攻击者状态。
5. **恢复效果加成**（仁心/抖擞/不懈）与**恢复类减伤**（济世）：在 `recoverTroops` 入口乘系数。
6. **战法发动率加成（条件式）**（机敏/英勇/筹算/熟虑/善谋/奔袭）：`moraleTriggerRate` 之后叠一层 `triggerRateBuff`（可按 战法类型 / 是否策略伤害 / 是否需准备 限定）。

**B 档（中）**
7. **控制时长 +1 回合**（惑言/慑心）：`inflictStatus` 施加控制时 `remaining += 1`（前 N 次）。
8. **统率/属性对比型减伤·增伤**（威势、泰阿 强固）：施加时按双方面板快照判定。
9. **受击触发叠层**（不屈、济世）：复用 `triggerFirstAidOnHurt` 式的受击钩子 + `stack: true`。
10. **计数型增伤**（蓄锐：每 2 次普攻 +X，可叠加；选锋：普攻后下次策略伤害 +X）：复用 `actLayerCounters` / `pending_stacks` 先例。
11. **火攻/燃烧/恐慌/妖术 命中判定后的 DoT 增伤**：DoT 已在"挂上时冻结"，需把增伤在冻结时计入（复用现有 `dotTypes`）。
12. **移除增益 / 移除负面**（破障、千钧）：`removeBuffFromTarget` 输出。
13. **攻击距离 +1 / 战法距离 +1**（穿杨/豪纵）：`General` 有效距离临时加成（引擎已有实时距离模块）。
14. **跳过准备回合**（谋断）：`PreparedActive` 的准备计时器减 1。
15. **首次受击规避 / 首次攻击额外目标**（避险、迸发、劲弩）：一次性标记 + 目标池扩展。

**C 档（大，建议单独排期）**
16. **击虚**：目标身上每有一层 DoT/控制，增伤 +3~9%（上限 5 种）——需要"按目标状态动态结算"。
17. **内政/政策类**（G12：商盈/税丰/富庶/采伐/植垦/取衡）：**不做**（属大地图经营，与战斗引擎无关）。

## 4. 引擎改动点

| 文件 | 改动 |
|------|------|
| `src/engine/types.ts` | `General.treasure?: TreasureLoadout`；`Status.sourceKind?: 'skill' \| 'treasure'`；新增若干净投入则加 `noAttack` 等字段 |
| `src/engine/treasure.ts`（新） | `buildTreasureStatuses(loadout): CreateStatus[]`——把宝物效果翻译成状态/输出，`source:'treasure'` |
| `src/engine/action.ts` `inflictStatus` | **宝物来源跳过冲突判定**（同类型直接叠加/共存，符合口径 3），并在施加时累加而非替换 |
| `src/engine/combat.ts` | 准备阶段最前（一类指挥之前）挂载宝物效果 |
| `src/engine/stats.ts` / `report.ts` | 战报展示宝物名 + 词条 + 数值；统计归属宝物 |
| `web/heroes.ts` `buildGeneral` | 透传 `treasure`；`web/data/*.json` 补宝物元数据 |

**关键：口径 3 的实现方式**——`inflictStatus` 中新增早退分支：
```ts
if (next.sourceKind === 'treasure') { pushStatus(...); return; }   // 不查冲突、不取高、不刷新
```

## 5. Web UI 方案（武将详情 → 佩戴宝物）

1. **入口**：武将详情弹窗新增「宝物」区块（当前：未佩戴 / `图标 + 名称 + 类型 + 品质`）。
2. **选择弹窗（三步，单弹窗内折叠）**
   - ① **选宝物**：38 件稀世网格（图标 + 名称 + 类型），点选后右侧显示 3 条自带特效与「该宝物词条池」；
   - ② **选词条**：展示该宝物的 6~7 条词条（名称 + 官方描述），单选；
   - ③ **选数值**：`<input type=range>` 滑杆，取值 = 官方区间内的合法梯级；滑杆刻度用**蓝 / 粉 / 红**三色渲染（数据来自 `AffixDef.hint`），并显示「蓝：5%~10% ｜ 粉：13% ｜ 红：15%」文字提示。
3. **默认值**：宝物默认「10 级」；词条默认不选（= 未锻造）；数值默认**红档（上限）**，可拖到任意档。
4. **数据流**：`SlotState.treasure` → `buildGeneral(..., treasure)` → 战报/模拟。
5. **展示**：配将槽位卡与战报头部显示宝物图标；战报详情中宝物效果单独一行（来源标注「宝物」）。
6. **复用**：伤害测试实验室同步支持（同一套 `renderSlot` / 详情弹窗）。
