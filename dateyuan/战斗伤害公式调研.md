# 战斗伤害公式调研

> 来源：社区战报反推，**非官方公布公式**。模拟器实现应以 golden test 校准。  
> 主要参考：[伤害影响因素篇一：总篇](https://news.dmzgame.com/stzb/gl/2022-08-05/4462.html)（作者：十面埋伏，2022）

---

## 一、兵力与伤害的关系

### 1.1 核心结论

**所有伤害（兵刃 / 谋略）都以兵力为基础**，但兵力不是简单的线性乘数，而是通过两条路径起作用：

| 路径 | 说明 |
|------|------|
| **兵力基础伤害** | 仅与当前兵力有关；兵力=0 则为 0；与战法伤害率**无关** |
| **主要伤害中的「单位伤害」** | 由兵力决定的一个因子，与伤害率、属性等**相乘** |

因此：**兵力越高 → 总伤害越高**；兵力下降时，两条路径都会缩水，且低兵力时波动更明显。

### 1.2 兵力基础伤害（实测锚点）

目标兵力充足时：

| 伤害类型 | 兵力=10000 时约值 | 备注 |
|----------|-------------------|------|
| 普通兵刃伤害 | **≈ 211** | 与伤害率无关 |
| 动摇伤害 | 普通兵刃的 **1/3** | |
| 普通谋略 / 火攻 | **≈ 108** | |
| 燃烧 / 恐慌 / 妖术 | 普通谋略的 **1/3** | |

### 1.3 主要伤害中的兵力曲线（单位伤害）

- 兵力 **< 3500**：主要伤害随兵力增长**很快**
- 兵力 **> 7000**：增长**明显变慢**
- 曲线上界存在，不会无限增长（例：洛阳守军 3 万兵伤害也未极高）

**宏观近似**（GameRes 等简化模型，用于阵容强度估算）：

- 伤害 ∝ **兵力^0.5**
- 战斗力 ∝ **兵力^1.5**（非线性，减轻纯兵力碾压）

> 引擎实现建议：M2 可用 `^0.5` 或查表拟合「单位伤害曲线」；M4 用 golden test 在 3500 / 7000 / 10000 等锚点校准。

### 1.4 特殊现象（与兵力相关）

1. **伤害率翻倍 ≠ 总伤害翻倍**：兵力基础伤害不随伤害率变化，故 200% 伤害率战法总伤害 < 2× 100% 普攻。
2. **低兵力仍能输出**：兵力≈0 时仍有「攻击基础伤害 / 谋略基础伤害」（纯属性项），故高属性低兵力武将（如马超）仍有威胁。
3. **伤害上限**：单次伤害不超过目标当前兵力。
4. **伤害与目标兵力无关**（除上限截断外）。

## 二、兵刃（物理）伤害计算公式

### 2.1 总公式

```
兵刃伤害 = 兵力基础伤害 + 攻击基础伤害 + 主要伤害
```

三部分**相加**，结构和谋略伤害对称。

### 2.2 兵力基础伤害

- **只与发动者当前兵力有关**
- 不受：攻击、防御、伤害率、增减伤影响

### 2.3 攻击基础伤害

- **与兵力无关**（兵力=0 时仍存在）
- **完全无视目标防御**
- 与伤害率成正比
- 受增减伤影响

**无增减伤、100% 伤害率时：**

| 类型 | 公式 |
|------|------|
| 普通兵刃 | `攻击属性 × 随机数`，随机数 ∈ **{0.30, 0.31, …, 0.39}** |
| 动摇 | `攻击属性 × 0.4`（无随机） |

> 这就是为什么同一武将连续两次普攻伤害不同（波动可达约 30%，低兵力时更明显）。

### 2.4 主要伤害

主要伤害 ≈ 四因子**相乘**：

```
主要伤害 = 单位伤害(兵力) × 伤害率 × 属性影响(攻防差) × 增减伤因子
```

| 因子 | 规则 |
|------|------|
| 单位伤害 | 见 1.3 兵力曲线 |
| 伤害率 | 兵刃战法伤害率通常**不受属性影响**（例外：令明负榇→速度，鹤翼分兵→谋略） |
| 攻防差 | `攻击 - 目标防御`（先结算无视防御%） |
| 属性影响曲线 | **-70 ≤ 攻防差 ≤ 130** 高收益区间；区间外边际递减，有上界 |
| 增减伤 | 攻击基础伤害 + 主要伤害 =「可变伤害」，共享增减伤；**所有增伤/减伤数值相加为单一总和**，因子 = max(10%, 1+Σ增伤−Σ减伤)（物理/谋略统一，2022 权威原文 OCR 复核）；总和 < **-90%** 时最低保留 **10%** |

**属性抵消**：主要伤害里 1 攻击 ≈ 抵消 1 防御，但攻击还增加「攻击基础伤害」，故 **1 攻击略优于 1 防御**。

### 2.5 兵刃伤害管道（引擎伪代码）

```
function calcPhysicalDamage(attacker, defender, damageRate, type):
  troopBase = lookupTroopBaseDamage(attacker.troops, type)  // 与 damageRate 无关
  atkBase = attacker.attack * getAtkBaseCoeff(type) * damageRate * buffMult
  main = unitDamage(attacker.troops) * damageRate
       * attrFactor(attacker.attack - effectiveDef(defender))
       * buffMult
  return min(troopBase + atkBase + main, defender.troops)
// buffMult = max(10%, 1 + Σ增伤 − Σ减伤)（单一总和；随机仅 getAtkBaseCoeff ∈ {0.3…0.39}，无宏观波动）
```

## 三、谋略（策略）伤害计算公式

### 3.1 总公式

```
谋略伤害 = 兵力基础伤害 + 谋略基础伤害 + 主要伤害
```

### 3.2 兵力基础伤害

- 同结构，数值低于兵刃（10000 兵约 108 vs 211）
- 燃烧 / 恐慌 / 妖术 = 普通谋略的 1/3

### 3.3 谋略基础伤害

- **与兵力无关**
- **与伤害率无关**
- 受目标谋略、增减伤影响

**无增减伤、目标谋略=0 时：**

| 类型 | 公式 |
|------|------|
| 普通谋略 / 火攻 | `谋略属性 × 0.5` |
| 燃烧 / 恐慌 / 妖术 | `谋略属性 × 0.25` |

### 3.4 主要伤害

```
主要伤害 = 单位伤害(兵力) × 有效伤害率 × 目标谋略影响 × 增减伤因子
```

#### 有效伤害率（多数谋略战法）

伤害率与谋略**线性**相关（战法描述「受谋略影响」时）：

```
有效伤害率 = 基础伤害率 + (谋略 - 80) × 伤害率增长率
```

- 例：众谋不懈 — 谋略=80 时 194%，每 +1 谋略 +1.925%
- 取整：按 **1%** 粒度，规则「八舍九入」
- 主要伤害确定后，**与发动者谋略再无直接关系**（谋略仅通过伤害率进入）

#### 目标谋略影响

- **与「双方谋略差」无关**（常见误区）
- 目标谋略 ≥ **52** 时，按阶梯阈值降低伤害（52, 54, 56, 58, 59, 61… 每档约 -1%）
- 52～109 区间降幅明显；>129 后边际很小
- 实战建议：目标谋略堆到约 **109** 性价比最高

#### 谋略增减伤特殊规则（官方承认的历史缺陷，引擎不建模，仅记录）

- 「造成的策略伤害降低」**不能**完全抵消「受到的策略伤害提高」（如大赏三军 vs 磐阵善守）
- 「受到的策略伤害降低」也**不能**抵消「造成的策略伤害提高」（大赏三军 60% 增伤被磐阵减伤时，可变伤害保留 60%，不会被降到 10%）
- **来源链**（2025-08 复核，均为权威社区来源）：
  - 《伤害影响因素总篇》4462 原文明述该规则并给出大赏/磐阵例子（2022-08-05 发布，晚于下方修复，说明该「增伤保护下限」部分在修复后仍存在）
  - 《减伤缺陷篇》问题答疑（自由指挥官原作 / 十面埋伏转发）：完整定义两条缺陷——① 受到侧减伤不能抵消造成侧增伤；② 减伤总和超过 100% 时超出部分无效；并确认**只有策略伤害受影响**；考古最早 2018-05（战报视频），2020-06 玩家@都督六合诸军事 发现【磐阵善守】下【绝水遏敌】伤害异常
  - 《2022年5月11日减伤修复分析》：官方 2022-05-11 例行更新修复「受到策略攻击的伤害降低」「某些情况计算错误」——修复了缺陷 ②（减伤可放心堆叠，磐阵/汉董卓增强），缺陷 ① 的「增伤保护下限」在 4462（2022-08）中仍被描述为现行行为
- **引擎决策**：该规则是官方承认的 bug，且修复后的精确数学形式从未公布（修复分析中「荀彧法正输出降低」的观测与「增伤保护下限」存在解释张力），模拟器（FlxSNX）也未实现——**引擎统一采用单一总和模型（max(10%, 1+Σ增伤−Σ减伤)），不建模该特殊规则**；如后续获得精确战报再补
- 参考：https://zhuanlan.zhihu.com/p/510892289 · https://zhuanlan.zhihu.com/p/512540893 · https://ds.163.com/article/627a2a7c849ee20001845f4c/

### 3.5 谋略伤害管道（引擎伪代码）

```
function calcStrategyDamage(attacker, defender, baseRate, growthRate, dotType):
  troopBase = lookupTroopBaseDamage(attacker.troops, dotType)
  stratBase = attacker.strategy * getStratBaseCoeff(dotType)
              * targetStratFactor(defender.strategy) * buffMult
  effectiveRate = roundRate(baseRate + (attacker.strategy - 80) * growthRate)
  main = unitDamage(attacker.troops) * effectiveRate
       * targetStratMitigation(defender.strategy) * buffMult
  return min(troopBase + stratBase + main, defender.troops)
// buffMult = max(10%, 1 + Σ增伤 − Σ减伤)（单一总和；策略特殊减伤规则不建模，见 §3.4）
```

## 四、兵力恢复计算公式

> 权威来源：十面埋伏《率土秘卷一：恢复效果》[知乎](https://zhuanlan.zhihu.com/p/454193204)（公式图 OCR 复核）+ 评论区实战战报反推验证。

### 4.1 恢复率（与伤害率同构，已确认无误）

```
恢复率 = 基础恢复率 + 恢复率增长率 × (谋略 - 80)，再按 1% 粒度「八舍九入」
```

- 基础恢复率 = 谋略 80 时的战法描述值（如三军之众 151%、皇裔流离 68%）
- 谋略 < 80 时本地采用 `基础×0.4 + 基础×0.6×(谋略/80)` 折减（模拟器 clacSkillAdditionRate 同款；十面埋伏文章未涉及 <80 情形，保留待校准）

### 4.2 恢复值（v0.14 修正，替代原「目标最大兵力 × 恢复率」错误实现）

```
恢复值 = floor( round( 300×施法者兵力 / (3500+施法者兵力) ) × 恢复率/100 × (1 + 恢复提高效果) )
```

- 单位伤害曲线与伤害公式**共用**（300×兵/(3500+兵)，先 round 再相乘，同模拟器 FlxSNX `calcRecover`）
- ⚠️ 原文为 **300×兵力（乘号）**，注意与 `(300+兵力)/(3500+兵力)`（加号）区分——OCR 公式图原文与实战数据均指向乘号
- **实战验证**（文章评论区 黑白猫 2025-06，与战报分毫不差）：刘备【皇裔流离】谋略 269 → 恢复率 68+0.6×189 = 181.4 → **181%**；兵力 9500 → round(300×9500/13000) = **219**；219×1.81 = 396.39 → **396** = 实际恢复
- **变量取值时机**：状态类恢复（休整/持续型急救）的兵力/谋略取「状态被施加那一刻」（挂上时冻结，如刘备发动皇裔流离之时）——引擎 first_aid 已按此冻结 `healTroops`；主动恢复取施法者结算时当前兵力
- **前提**：伤兵充足 + 目标非围困（禁疗）；恢复提高效果极罕见（宝物【博浪】抖擞、锻造【仁心】），引擎未建模按 1
- **引擎实现**：`formulas.calcHealAmount(troops, rate, healBoost=0)` → `Math.floor(Math.round(unitDamage(troops)) * (rate/100) * (1+healBoost))`；实际恢复量再受伤兵池/兵力缺口截断（`recoverTroops`）
- **遗留疑问**：评论区反馈主动恢复类（增援/合流）与公式不符（目标兵力越少恢复越多），可能是主动恢复变量取值不同——待真实战报校准（至少 1 组）

## 五、通用修正因子

| 因子 | 兵刃 | 谋略 |
|------|------|------|
| 兵种克制 | 减伤（不增伤） | 减伤 |
| 无视属性 | 无视防御 % | 无视谋略 %（多个效果数值相加） |
| 随机波动 | 攻击基础随机 0.3～0.39（**无宏观 ±5% 波动**——旧调研误加，权威文章仅承认攻击基础随机数，模拟器亦无，v0.14 已从引擎删除） | 普通谋略无此项随机 |
| 输出构建（配将） | 伤害率 × 增伤 × 属性影响 | 战法(增长率) × 增伤 × 属性影响 |

## 六、对模拟器实现的建议

### v1 引擎优先级

1. **必做**：三部分相加结构；兵力基础 + 单位伤害曲线；攻防差 / 目标谋略阶梯
2. **必做**：攻击基础随机（0.3~0.39，唯一随机源）；谋略伤害率线性成长 + 八舍九入
3. **必做（v0.14 已实现）**：恢复值 = floor(round(300×施法者兵力/(3500+兵力)) × 恢复率/100 × (1+恢复提高))；增减伤单一总和 max(10%, 1+Σ)
4. **次优先**：动摇/DOT 系数差异；主动恢复类（增援/合流）变量取值待战报校准
5. **校准**：以 10+ 组真实战报 golden test 反推曲线参数，勿迷信简化 `^0.5` 一步到位

### 已知近似 / 风险

- 单位伤害曲线的精确函数未公开，总篇仅有定性描述 + 锚点（300×兵/(3500+兵) 为模拟器拟合 + 战报验证）
- GameRes 的 `^0.5` 是宏观估算，与三部分模型并存时使用场景不同
- 不同战法类型（指挥锁定 vs 主动实时）结算时机不同，公式之外还有**释放时机**问题
- 策略减伤特殊规则（§3.4）为官方历史缺陷，修复后精确规则未公布，引擎不建模
- 物理伤害取整：模拟器对三部分未取整之和做 round；引擎对每部分先 round 再求和（差异 ≤2）
